01 / YOUR TURN

이제, 네가 만들고 싶은 것

매일 겪는 작은 불편 하나를 골라요. 이번에는 프로젝트의 이름과 규칙을 직접 정합니다.

“이런 앱 하나 있으면 좋겠는데.”
그 말을 첫 화면으로 바꿔봐요.

물품 대여소

빌릴 수 있는 물건 찾기 → 신청 → 반납 확인

동아리 전시관

작품 올리기 → 검색 → 반응 살펴보기

학급 행사 도우미

의견 받기 → 일정 만들기 → 결과 정리

필요한 기능 세 개만 고르기

물품 대여소는 예약·정원 + 반환 상태 + 검색을 조합할 수 있어요. 전시관은 사진 + 검색 + 통계를, 행사 도우미는 설문 + 일정 + 보고서를 골라보세요. 이 보드는 기능을 고르는 연습이며 실제 앱을 만들거나 Google에 연결하지 않습니다.

문제누구의 어떤 불편?
첫 버전작게 만들고 실행
친구 테스트설명 없이 사용
개선막힌 한 곳 고치기

기능이 많은 앱보다, 내가 정한 일을 끝까지 할 수 있는 앱이 이번 목표예요. 배운 기술을 전부 넣을 필요는 없어요.

02 / ONE PROBLEM, THREE FEATURES

누가, 언제, 무엇 때문에 불편할까요?

“멋진 학교 앱”보다 “점심시간에 배드민턴 라켓을 빌릴 수 있는지 확인하는 앱”처럼 좁혀요.

  1. 사용할 사람과 불편한 순간을 한 문장으로 써요.예: 체육부원이 점심시간에 남은 라켓을 확인하기 어려워요.
  2. 꼭 필요한 기능 세 개를 동작으로 적어요.예: 남은 물건 찾기 / 대여 신청하기 / 담당자가 반납 완료로 바꾸기.
  3. 성공 장면과 다음에 할 일을 따로 적어요.성공: 친구가 빈 물건을 찾아 한 번 신청한다. 다음: 알림·꾸미기·추가 종목.
고등학생이 쓸 작은 서비스를 만들고 싶어. 나는 코드를 읽지 못해.
앱 이름: [내가 정한 이름]
쓸 사람과 불편한 순간: [누가, 언제, 무엇 때문에 불편한지]
꼭 필요한 기능 세 개: [기능 1] / [기능 2] / [기능 3]
성공했다고 볼 장면: [친구가 어떤 일을 끝내면 되는지]
이번에는 하지 않을 일: [다음 버전으로 미룰 것]
Google Workspace와 앞에서 배운 기능으로 만들 수 있는 순서를 제안해줘.
아직 코드는 주지 말고 화면, 필요한 도구, 기능별 확인 방법을 쉬운 말로 정리해줘.
첫 번째로 완성할 기능 하나를 추천해줘. 어려운 부분은 더 작은 방법을 제안해줘.
내가 비워둔 내용과 중요한 규칙만 물어보고, 확인하지 않은 기능을 가능하다고 단정하지 마.

대괄호를 채워 보내고, 실제로 쓸 사람이 원하는지 확인해요. AI가 더 많은 기능을 제안하면 첫 버전의 세 기능만 남깁니다.

대여라면 “언제까지 빌리나”, 전시관이라면 “누가 올리나”, 행사라면 “한 신청이 일정 하나인가”를 먼저 정해요. 규칙이 정해져야 같은 결과를 시험할 수 있어요.

04 / PREPARE A CLEAN WORKSPACE

내 프로젝트의 작업 공간 만들기

앞선 앱의 실제 기록을 바꾸지 않도록 새 연습 자료로 시작합니다.

  1. Docs에 기획·파일 보관·테스트 기록 칸을 만들어요.v1: 첫 동작 / v2: 세 기능 연결 / v3: 친구 테스트 후 개선. 단계마다 작동한 파일 전체와 날짜를 보관해요.
  2. 새 Apps Script 프로젝트와 필요한 Google 자료만 준비해요.저장이 필요하면 새 Sheets, 사진이면 새 Drive 폴더. 자동화는 3회의 시트 연결 프로젝트 흐름을 참고해요.
  3. 설정 이름·자료 주소·공유 범위를 기록해요.AI에게 설정을 적을 표를 요청하고 속성 화면에 넣어요. API 키·취소용 비밀값은 공유 Docs나 채팅에 넣지 않아요.

예약·사진·반환

남은 수량은 서버에서 확인. 중복 신청 방지. 사진 크기·형식 제한. 반환 처리는 담당자만.

자동화·보고서

같은 신청으로 일정이 두 번 생기지 않기. 실패한 부분부터 재시도. 원본 문서 보존.

API·질문 답변

날짜·출처·불러온 시각 표시. 실패와 자료 없음 구분. AI API는 5회의 이용 조건을 확인한 경우만.

사진을 보여주는 앱은 웹 앱 이용자에게 사진이 전달돼요. Drive 폴더가 비공개라는 이유만으로 안전하다고 생각하지 말고 앱의 이용 범위를 확인해요.

05 / MAKE THE FIRST SCREEN

기획을 눈앞의 화면으로

한 번에 세 기능을 연결하기 전에, 친구가 무엇을 누를지 보이는 첫 화면을 만들어요.

내가 결정한 기획을 아래에 붙일게. 이 기획으로 첫 화면을 만들어줘.
[확정한 기획 붙이기]
브라우저에서 열 수 있는 index.html 전체를 줘. 코드 일부를 바꾸라고 하지 마.
외부 라이브러리 없이, 첫 번째 기능을 시작하고 결과를 보는 길이 잘 보이게 해줘.
세 기능의 버튼과 필요한 입력칸을 만들되 지금은 연습용 데이터로 화면만 보여줘.
연습용 데이터라고 표시하고 아직 실제 저장·업로드·예약이 되었다고 안내하지 마.
빈 화면, 잘못 입력한 경우, 처리 중, 실패했을 때의 안내도 준비해줘.
휴대폰에서 글자와 버튼이 잘 보이고 키보드로도 이용할 수 있게 해줘.
파일 전체를 어디에 넣고 어떻게 열어볼지 순서대로 알려줘.
  1. AI의 실행 미리보기 또는 저장한 index.html을 열어요.아직 Google 연결 전이므로 로컬 파일로 화면을 확인할 수 있어요. 확장자는 .html이에요.
  2. 처음 보는 친구 입장에서 시작 버튼을 찾아요.한 번 누른 뒤 무엇이 일어나는지, 지금은 연습 데이터인지 읽어봐요.
  3. 현재 화면과 기획을 Docs에 보관해요.원하는 동작과 다르면 같은 채팅에서 결과를 말하고 파일 전체를 다시 받아요.

06 / CONNECT ONE AT A TIME

첫 번째 기능을 끝까지 연결하기

첫 기능이 확인되면 같은 순서로 두 번째와 세 번째를 연결해요. 화면과 서버의 약속을 함께 맞춥니다.

현재 기획과 index.html 전체를 줄게. 이번에 연결할 기능은 [기능 하나]야.
그 기능에 필요한 Code.gs 전체를 만들어줘. 기존 기능이 있다면 함께 유지해줘.
이 프로젝트의 index.html을 여는 웹 앱으로 만들고 필요한 Google 도구만 연결해줘.
실제 데이터의 입력·저장·조회 규칙을 기획에 맞춰 정리해줘.
시트·폴더·달력 주소와 키는 코드 줄을 고치지 않게 설정 화면에서 넣고 싶어.
필요한 설정 이름과 넣을 값의 종류를 표로 줘. 비밀값 자체는 나에게 묻지 마.
입력값을 서버에서도 확인하고 같은 요청을 다시 눌러도 기록이 중복되지 않게 해줘.
다른 사람의 기록을 마음대로 바꾸지 못하게 하고 담당자 작업은 따로 보호해줘.
기존 자료를 지우거나 열 구조를 바꿔야 한다면 먼저 이유와 보존 방법을 알려줘.
실패하면 성공이라고 표시하지 말고 이유와 다시 시도하는 방법을 알려줘.
화면이 부를 동작과 받을 결과를 정리해줘. 아직 연결하지 않은 기능은 구분해줘.
초기 준비, 설정 입력, 직접 실행해 확인할 방법을 클릭 순서로 설명해줘.
  1. Apps Script의 Code.gs에 받은 파일 전체를 붙여요.HTML 파일을 추가해 이름을 index로 정하고 받은 index.html 전체를 넣어요. 기존 파일은 Docs에 먼저 보관해요.
  2. 프로젝트 설정 → 스크립트 속성에 안내받은 설정을 넣어요.자동화 프로젝트는 시간대·트리거도 3회에서 확인한 방식으로 준비해요. 모든 프로젝트에 트리거가 필요한 것은 아니에요.
  3. AI가 안내한 준비 동작을 실행해요.새 연습 자료에 필요한 탭·열만 만들어졌는지 확인해요. 권한 화면과 실제 사용하는 도구가 다르면 선생님과 살펴봐요.
현재 index.html과 Code.gs 전체를 함께 줄게. [이번 기능]이 끝까지 작동하게 연결해줘.
Apps Script에서 연 웹 앱 화면이 google.script.run으로 내 서버를 부르게 해줘.
성공하면 서버가 확인한 결과를 보여주고 연습용 데이터로 덮어쓰지 마.
처리 중에는 중복 클릭을 막고, 실패하면 다시 누를 수 있게 안내해줘.
늦게 도착한 예전 결과가 지금 화면을 덮지 않게 해줘.
미연결 기능은 준비 중으로 표시하고 기존에 확인한 기능은 유지해줘.
바뀐 파일은 일부가 아니라 전체로 각각 줘. 변경이 없는 파일은 그대로라고 알려줘.
배포하는 클릭 순서와 이 기능이 진짜 작동했는지 확인할 방법을 알려줘.
실제로 저장하는 기능은 새로고침 후 화면과 Google 자료를 대조하게 해줘.
  1. 처음에는 배포 → 새 배포 → 웹 앱으로 만들어요.실행 계정과 접근 범위는 학교에서 허용한 범위로 정해요. 친구 테스트 전에는 제한된 범위에서 시험해요.
  2. /exec로 끝나는 웹 앱 주소를 열고 첫 기능을 써봐요.화면의 성공 안내만 믿지 말고 Sheets·Drive·Calendar 등 실제 결과를 대조해요. API는 원자료와 날짜를 대조해요.
  3. 파일을 고쳤다면 기존 배포를 새 버전으로 갱신해요.이제 로컬 HTML 대신 웹 앱 주소로 확인해요. 03·04 프롬프트에 다음 기능을 넣어 반복해요.

참고: Google · 웹 앱 배포와 실행 계정 ↗

07 / CHECK WHAT REALLY HAPPENS

잘될 때도, 안 될 때도 확인하기

세 기능이 연결되면 v2로 보관해요. 기획에 적은 성공 장면이 실제로 되는지 시험합니다.

  1. 정상 입력 / 빈 입력 / 결과 없음각각 예상하는 화면을 먼저 적어요. 자료가 없는 경우와 오류를 구분해요.
  2. 같은 버튼 두 번 / 새로고침 후 다시 확인기록이 두 개 생기거나 결과가 사라지는지 실제 자료까지 봐요. 저장하지 않는 앱은 해당 없음으로 적어요.
  3. 실패 안내 / 허용된 다른 계정과 휴대폰연습용 설정에서만 연결 실패를 시험해요. 친구가 열 수 있는지, 담당자 기능이 노출되는지 확인해요.

테스트 표: 한 행동 → 예상 결과 → 실제 결과 → 통과·수정 필요·미실행·해당 없음. AI가 만든 표의 결과 칸은 내가 실행한 뒤 채웁니다.

직접 확인한 뒤 체크하세요.

08 / DESCRIBE, FIX, CHECK

“안 돼요”를 고칠 수 있는 설명으로

오류를 만나면 새 앱부터 다시 만들기보다, 같은 문제가 생기는 순서를 찾습니다.

내가 한 일

“파란 우산을 선택하고 대여 신청을 두 번 눌렀어.”

실제로 일어난 일

“성공 안내는 한 번인데 시트에는 두 줄이 생겼어.”

원하는 결과

“같은 신청은 한 건만 남고 남은 수량도 한 번만 줄어야 해.”

사용한 웹 앱 주소의 종류(/exec), 배포 버전, 오류 문구도 적어요. 키·취소용 비밀값·개인정보는 가리고 전달해요.

내 앱에서 생긴 문제 하나를 고치고 싶어. 나는 코드를 읽지 못해.
문제가 생기는 순서: [입력한 값과 누른 버튼을 차례로 적기]
원하는 결과: [원래 되어야 하는 일]
실제 결과와 오류 문구: [직접 본 사실, 비밀값과 개인정보는 가리기]
사용 환경과 최근 바꾼 점: [기기, /exec 여부, 배포 갱신 여부, 바꾼 기능]
현재 파일 전체와 확인한 설정 이름을 줄게. 원인을 아직 모르면 확인할 일을 하나씩 알려줘.
작동하던 다른 기능과 저장 자료를 유지하면서 이 문제부터 고쳐줘.
파일을 바꾸면 수정한 전체 파일과 달라진 행동을 설명해줘.
같은 순서로 다시 시험하는 방법과 기존 기능도 확인할 방법을 줘.
직접 실행하지 않은 결과를 해결 완료라고 쓰지 마.
  1. 수정 전 파일과 연습 자료를 보관해요.AI가 저장 구조 변경을 요구하면 기존 기록을 보존하는 방법부터 확인해요.
  2. 수정 파일 전체와 필요한 설정을 적용하고 배포를 갱신해요.새로고침 뒤 화면에 적은 버전과 방금 배포한 버전이 같은지 확인해요.
  3. 문제가 생겼던 순서와 정상 사용을 다시 시험해요.안 고쳐졌다면 실제 결과를 추가해요. 다른 기능까지 망가졌다면 작동한 버전으로 돌아가 범위를 줄여요.

09 / LET A FRIEND TRY

옆에서 설명하지 않고 지켜보기

친구에게 앱 사용법 대신 끝내야 할 일을 줘요. 멈춘 순간이 다음 개선의 단서입니다.

내 기획과 지금 작동하는 기능을 줄게. 친구 테스트용 미션 세 개를 만들어줘.
버튼 이름이나 누르는 순서를 알려주지 말고 달성할 일만 말해줘.
예: ‘점심시간에 빌릴 수 있는 라켓을 찾아 한 번 신청해봐.’
아직 만들지 않은 기능이나 담당자 전용 작업을 일반 친구에게 시키지 마.
개인정보 대신 연습 자료와 별칭으로 진행하게 해줘.
미션마다 완료 여부, 멈춘 곳, 실제로 한 말, 내 관찰을 적을 빈칸을 줘.
사용 기록을 지어내지 말고 테스트를 못 했다면 미실행으로 남겨줘.
마지막에 ‘다음에 또 쓰고 싶은가, 무엇 때문에 그런가’를 물어보게 해줘.
  1. 허용된 친구 계정으로 앱을 열고 미션 하나를 줘요.접속 자체가 안 되면 그 사실부터 기록해요. 이용 범위를 넓히기 전에 학교 정책과 배포 설정을 확인해요.
  2. 친구가 직접 누르는 동안 답을 먼저 알려주지 않아요.멈춘 위치와 한 말을 적어요. 도움을 줬다면 “도움 후 완료”로 구분해요.
  3. 친구가 끝낸 뒤 가장 불편했던 점을 들어요.친구 이름 대신 테스터 A·B로 기록하고, 테스트용 신청·사진을 실제 운영 자료와 구분해요.

테스트하지 않았다면 미실행이라고 기록해요.

10 / MAKE ONE THING BETTER

친구의 관찰을 수정 요청으로

원인을 단정하기 전에 실제 기록을 보고, 가장 중요한 문제 한 가지를 고릅니다.

먼저 · 잘못되는 일

저장 실패·중복 신청·남의 기록 변경. 자료와 이용 권한부터 바로잡아요.

그다음 · 못 끝내는 일

버튼을 못 찾음·안내를 이해 못 함. 미션을 완료할 수 있게 바꿔요.

나중 · 더 예뻐지는 일

색·장식·추가 효과. 핵심 동작이 된 뒤 내 취향을 더해요.

친구 테스트 뒤 내 앱을 한 가지 개선하려고 해.
친구에게 준 미션: [끝내야 했던 일]
실제로 관찰한 일: [멈춘 곳, 친구가 한 말, 도움을 줬는지]
이번에 바꿀 것: [개선 한 가지]
좋아졌다고 볼 기준: [같은 미션에서 확인할 행동]
현재 파일 전체를 줄게. 기존 기능과 자료는 유지하고 이번 변경을 반영해줘.
수정한 파일 전체를 각각 주고 배포에 반영할 순서도 알려줘.
바꾼 부분과 관련된 기능을 다시 시험할 목록을 줘.
내가 다시 관찰한 뒤 결과를 적게 해줘. 성공했다고 미리 쓰지 마.

예: 수정 전에는 친구가 버튼을 찾지 못했어요. 수정 후에는 같은 미션을 설명 없이 끝냈는지 봐요. 정말 더 나아졌는지 내가 확인합니다.

가능하면 처음 쓰는 다른 친구도 시험해요. 같은 친구가 다시 썼다면 익숙해진 영향도 있을 수 있다고 기록해요. 테스트를 못 했다면 다음 확인으로 남겨요.

11 / SHARE A WORKING VERSION

완성 파일과 사용 방법을 함께 남기기

내일 다시 열었을 때도 이어서 만들 수 있도록, 실행 주소와 작동한 버전을 정리합니다.

현재 기획, 최종 파일, 실제 테스트 기록을 줄게. 내 서비스 소개를 정리해줘.
누구의 어떤 문제를 해결하는지, 완성한 세 기능과 사용하는 순서를 적어줘.
최종 파일 이름, 필요한 설정 이름, 준비할 Google 자료를 목록으로 정리해줘.
API 키나 취소용 비밀값은 쓰지 말고 설정 위치만 설명해줘.
v1 첫 동작, v2 기능 연결, v3 개선에서 실제로 바뀐 점을 정리해줘.
파일 저장과 배포 갱신의 차이, 이전 버전으로 돌아갈 방법을 클릭 순서로 알려줘.
되돌려도 시트 기록과 설정까지 자동 복구되는 것은 아니라는 점을 설명해줘.
확인한 기능, 수정이 필요한 점, 미실행 테스트를 구분해줘.
공유 범위와 앱·트리거·외부 API 사용을 마치는 방법도 정리해줘.
내 테스트 기록에 없는 성과와 사용자 반응을 만들지 마.
  1. 작동한 파일 전체를 v3로 보관하고 화면에 버전 표시를 요청해요.예: v3 · 신청 버튼 안내 개선. 실제 확인 날짜와 남은 문제를 함께 적어요.
  2. 배포 → 배포 관리 → 현재 배포 편집 → 새 버전 → 배포.기존 배포를 갱신하면 같은 /exec 주소를 이어서 쓸 수 있어요. 친구 계정에서 새로고침해 버전과 핵심 동작을 확인해요.
  3. 문제가 생기면 배포 관리에서 작동했던 이전 버전을 선택해요.코드가 돌아가도 데이터·속성·트리거는 별도예요. 자료 변경은 보관본을 대조하고 함부로 덮어쓰지 않아요.

12 / KEEP BUILDING

다음 아이디어도 이렇게 시작하면 돼요

문제를 작게 나누고, 필요한 도구를 골라 연결하고, 실제 결과로 고치는 방법을 배웠습니다.

“이건 어떻게 만들지?”
이제 첫 질문을 할 수 있어요.

문제를 설명하기 → 작은 첫 버전 만들기 → 필요한 기능 연결하기 → 안 되는 이유 찾기 → 사람에게 써보게 하기. 이 과정을 다음 아이디어에도 가져가세요.

모든 서비스를 한 번에 만들 수 있다는 뜻은 아니에요. 새로운 기술·비용·이용 조건이 필요하면 확인하고, 지금 만들 수 있는 작은 부분부터 시작할 수 있어요.

내 기록을 Docs에도 옮겨두세요.

새로 만들고 싶은 것이 있어. [누구의 어떤 불편인지]를 해결하고 싶어.
지금 해본 일은 화면 만들기, 저장, 예약, 자동화, 사진 검색, 외부 정보 연결이야.
가장 작게 실행해볼 수 있는 첫 동작 하나를 제안해줘.
배운 도구로 할 수 있는 것과 새로 확인할 기술·비용·이용 조건을 구분해줘.
아직 모르는 점은 확인할 질문으로 남기고 가능하다고 단정하지 마.
먼저 화면과 확인 방법만 함께 정하자. 내가 결정하면 파일 전체를 요청할게.
