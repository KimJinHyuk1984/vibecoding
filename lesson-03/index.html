02 / ONE ROW, ONE ACTIVITY

신청 한 줄은 활동 한 건

이번 신청은 참가자별 예약이 아니라, 동아리가 할 활동 하나를 등록하는 신청이에요.

  1. 새 AI 채팅과 Docs ‘3회_동아리 자동 비서’를 만들어요.이전 프로젝트는 보관하고, 이번 작업은 같은 새 채팅에서 이어가요.
  2. Forms ‘3회_동아리 활동 신청’을 만들어요.다음 질문표의 이름과 형식을 사용해요. 실명·명단·이메일은 수집하지 않아요.
  3. 응답을 새 시트 ‘3회_동아리 운영’에 연결해요.아래 응답 탭 이름을 ‘신청’으로 바꿔요. 한 팀의 담당자 한 명이 시트·캘린더·문서를 준비해요.

03 / MY FIRST HELPER

시트에 나만의 메뉴 만들기

처음에는 신청 옆에 활동번호와 결과를 적을 칸을 준비하는 작은 도구부터 만들어요.

동아리 활동 신청을 관리하는 Google Sheets 도구를 만들고 싶어.
이 시트에서 확장 프로그램 → Apps Script를 열어 Code.gs에 붙일 거야.
시트 전체 주소는 프로젝트 설정의 SHEET_URL에 넣을게.
시트에 ‘동아리 도우미’ 메뉴와 ‘활동 관리 준비’ 항목을 만들어줘.
메뉴는 시트를 다시 열면 나타나고, 눌렀을 때만 준비 작업을 해줘.
‘신청’ 탭의 질문은 활동명, 활동 날짜, 시작 시각, 종료 시각, 장소, 계획한 일이야.
기존 응답 오른쪽에 활동번호, 일정상태, 일정ID, 실제참여인원, 한일, 느낀점 칸을 준비해줘.
보고서상태, 문서주소, PDF주소, 오류 칸도 만들고 필요한 관리 정보는 더 추가해도 돼.
원래 응답과 기존 값은 보존하고, 준비를 두 번 해도 열이 중복되면 안 돼.
활동번호는 행 위치가 바뀌어도 같은 활동을 알아볼 수 있는 고유한 값이어야 해.
각 활동에 번호를 처음 한 번만 부여하고 빈 줄과 제목 줄은 처리하지 마.
아직 일정·문서는 만들지 말고, 바로 붙여넣을 Code.gs 전체를 줘.
  1. 새 시트에서 확장 프로그램 → Apps Script를 열어요.프로젝트 이름은 ‘3회_동아리 자동 비서’. 받은 Code.gs 전체를 붙이고 저장해요.
  2. 프로젝트 설정의 스크립트 속성에 SHEET_URL을 추가해요.값에는 새 시트 주소 전체를 붙이고 저장해요. 프로젝트 시간대는 Asia/Seoul로 맞춰요.
  3. 시트로 돌아와 새로고침하고 ‘동아리 도우미’를 열어요.‘활동 관리 준비’를 누르고 필요한 권한을 확인해요. 이번 메뉴 도구는 웹 앱 배포가 필요 없어요.

참고: Google · 시트 맞춤 메뉴 ↗

04 / MAKE ONE EVENT

메뉴로 일정 하나부터 등록하기

자동화 전에 내가 눌러서 일정이 정확히 생기는지 먼저 확인해요.

  1. 컴퓨터에서 Calendar를 열고 새 캘린더를 만들어요.‘다른 캘린더’ 옆 + → 새 캘린더 만들기. 이름은 ‘3회_동아리 연습’, 시간대는 서울로 정해요.
  2. 그 캘린더 설정의 ‘캘린더 통합’에서 캘린더 ID를 복사해요.브라우저 주소가 아니라 캘린더 ID예요. 기본 개인 캘린더와 구분해요.
  3. Apps Script의 스크립트 속성에 CALENDAR_ID를 추가해요.값은 방금 복사한 ID. 시트의 파일 → 설정에서도 시간대를 서울로 맞춰요.

참고: Google · 새 캘린더 만들기 ↗

지금 Code.gs에 ‘동아리 도우미 → 선택 활동 일정 등록’을 추가해줘.
선택한 셀이 있는 ‘신청’ 탭의 활동 한 줄만 처리해줘.
일정은 설정의 CALENDAR_ID 캘린더에 만들어줘.
활동명, 날짜, 시작·종료 시각, 장소와 계획한 일을 사용해줘.
날짜 입력은 YYYY-MM-DD, 시각은 HH:mm이고 모두 한국 시간 기준이야.
시트가 날짜나 시간을 자동 변환한 경우도 원래 뜻대로 읽어줘.
실제로 없는 날짜, 빠진 내용, 종료가 시작보다 이르거나 같은 경우는 만들지 마.
활동번호를 먼저 저장하고 일정 설명에도 같은 번호를 넣어줘.
성공한 일정ID와 ‘등록 완료’를 남겨줘. 같은 활동을 다시 눌러도 일정은 하나여야 해.
동시에 실행되거나 중간에 멈춰도 번호로 기존 일정을 확인한 뒤 처리해줘.
등록 여부가 불확실하면 새 일정을 만들지 말고 ‘확인 필요’와 이유를 남겨줘.
초대자·알림 이메일은 추가하지 말고 기존 일정과 응답을 지우지 마.
메뉴 선택이 잘못됐거나 오류가 나면 무엇을 확인할지 알려줘.
기존 준비 기능을 유지하고 바뀐 Code.gs 전체를 줘.
  1. 새 Code.gs 전체를 붙이고 저장한 뒤 시트를 새로고침해요.권한이 추가되면 확인해요. 앞으로 메뉴를 추가할 때도 같은 순서예요.
  2. 첫 활동 줄의 셀 하나를 누르고 ‘선택 활동 일정 등록’을 실행해요.제목 줄이나 여러 줄을 선택하지 않아요.
  3. Calendar에서 날짜·시작·종료·장소를 확인해요.같은 메뉴를 한 번 더 눌러 일정이 늘지 않는지 확인해요. 잘되면 코드와 결과를 ‘v1 · 메뉴로 일정’으로 보관해요.

직접 확인한 뒤 체크하세요.

05 / FROM CLICK TO AUTOMATIC

새 신청이 오면 저절로 실행하기

트리거는 ‘어떤 일이 일어나면 이 작업을 시작해’라고 연결해 두는 장치예요.

메뉴로 일정 등록이 잘돼. 이제 Forms에 새 신청이 오면 자동으로 하고 싶어.
시트에 연결한 ‘양식 제출 시’ 트리거에서 쓸 함수 이름은 onClubFormSubmit으로 해줘.
자동 실행에서는 내가 선택한 셀이 아니라 방금 응답이 들어온 줄을 처리해줘.
새 활동의 관리 칸과 활동번호를 준비한 뒤 기존 일정 등록 기능을 사용해줘.
메뉴와 자동 실행이 같은 활동을 처리해도 일정은 하나여야 해.
자동 실행 중에는 팝업을 띄우지 말고 그 줄의 상태·오류 칸과 실행 기록에 남겨줘.
응답 정보 없이 편집기에서 실행하면 이유를 알려주고 일정을 만들지 마.
기존 신청을 한꺼번에 처리하거나 트리거를 코드에서 자동 설치하지 마.
지금 메뉴들은 유지하고 Code.gs 전체를 줘.
내가 트리거 화면에서 고를 항목도 짧게 알려줘.
  1. 코드를 저장한 뒤 Apps Script 왼쪽 시계 모양 ‘트리거’를 열어요.‘트리거 추가’에서 실행할 함수는 onClubFormSubmit을 골라요.
  2. 이벤트 소스는 ‘스프레드시트에서’, 유형은 ‘양식 제출 시’.폼에 연결한 이 시트의 제출 이벤트예요. 저장하고 권한을 확인해요. 같은 트리거를 중복 설치하지 않아요.
  3. 응답자용 링크에서 새 연습 활동을 제출해요.기존 줄 수정이나 편집기의 실행 버튼으로 대신 시험하지 않아요.

참고: Google · 설치형 트리거 ↗

새 응답 줄에 활동번호·일정ID·등록 완료가 생겼나요? Calendar에도 새 활동의 일정 하나가 보여야 해요.

트리거는 설치한 사람의 권한으로 실행돼요. 담당자가 캘린더를 수정할 수 있어야 합니다. 시트 셀 편집이나 코드로 행 추가는 ‘폼 제출’과 달라요. 실패하면 Apps Script의 실행 목록에서 해당 시각을 확인해요.

직접 확인한 뒤 체크하세요.

06 / RECORD WHAT HAPPENED

계획과 실제 결과는 달라요

계획을 보고서에 그대로 복사하기 전에, 실제로 무엇을 했는지 사람이 기록해야 해요.

실제참여인원

실제 참여한 인원수. 실습 예시는 4명.

한일

예: 식물 세 종류를 관찰하고 특징을 기록했다.

느낀점

예: 같은 장소에서도 잎 모양이 서로 달랐다.

실습에서는 [연습] 활동의 가상 결과임을 밝혀요. 실제 보고서에서는 한 일과 인원을 확인해 적고, AI가 하지 않은 활동을 만들어내게 하지 않아요.

  1. 보고서로 만들 활동 줄을 하나 정해요.등록 완료된 [연습] 활동에서 결과 입력을 연습해요.
  2. 오른쪽 세 칸에 인원·한 일·느낀 점을 입력해요.실제참여인원은 0 이상의 정수로 입력해요. 빈 결과를 AI가 채우게 하지 않아요.
  3. 활동번호와 계획 칸은 그대로 두고 결과를 읽어봐요.오타와 빠진 내용을 고친 뒤 문서를 만들어요.

07 / MAKE A REUSABLE FORM

보고서의 모양을 먼저 정해요

템플릿은 내용이 들어갈 자리를 표시한 원본 양식이에요. 완성 문서는 원본의 사본으로 만듭니다.

동아리 활동 보고서의 원본 양식을 만들고 싶어.
Google Docs 본문에 그대로 붙일 짧은 양식만 써줘.
제목은 ‘동아리 활동 보고서’로 하고 아래 표시칸을 빠짐없이 한 번씩 넣어줘.
{{활동번호}}, {{활동명}}, {{활동날짜}}, {{시작시각}}, {{종료시각}}, {{장소}}
{{계획한일}}, {{실제참여인원}}, {{한일}}, {{느낀점}}
표시칸의 글자와 중괄호는 그대로 두고, 사람이 읽을 항목 제목을 붙여줘.
한 탭의 일반 본문으로 만들고 표·머리말·꼬리말·이미지는 넣지 마.
실제 활동 내용은 아직 채우지 말고, 코드나 설명도 양식에 섞지 마.
  1. 새 Docs ‘3회_활동 보고서 양식’을 만들어요.AI가 준 양식만 본문에 붙여요. {{한일}} 같은 표시칸은 지우거나 중간에 줄바꿈하지 않아요.
  2. Drive에 ‘3회_완성 보고서’ 폴더를 만들어요.원본 양식과 완성본을 구분해요. 학생 전체에 편집 권한을 열 필요는 없어요.
  3. Docs 주소 전체와 결과 폴더 주소 전체를 보관해요.만든 담당자가 두 곳에 접근할 수 있는지 확인해요.

TEMPLATE_URL

보고서 원본 Docs의 전체 주소.

OUTPUT_FOLDER_URL

완성 보고서를 담을 Drive 폴더의 전체 주소.

Apps Script → 프로젝트 설정 → 스크립트 속성에 추가해요. 기존 SHEET_URL·CALENDAR_ID는 유지해요. 주소에서 ID만 잘라내거나 코드 줄을 고치지 않아요.

08 / FILL THE TEMPLATE

내 기록으로 문서 한 장 만들기

새 Code.gs를 AI에게 요청해서 메뉴를 확장해요. 문서를 만든 뒤 시트와 내용을 직접 대조합니다.

지금 도우미에 ‘선택 활동 보고서 만들기’ 메뉴를 추가해줘.
선택한 활동 줄의 계획과 내가 입력한 실제 결과로 보고서를 만들어줘.
TEMPLATE_URL의 원본 Docs를 복사해 OUTPUT_FOLDER_URL 폴더에 넣어줘.
앞에서 정한 {{활동번호}}부터 {{느낀점}}까지 표시칸 열 개를 해당 값으로 채워줘.
인원은 0 이상의 정수인지, 결과 칸은 비어 있지 않은지 먼저 확인해줘.
기록에 없는 내용은 지어내지 마. 원본 양식과 다른 파일도 바꾸지 마.
파일 이름에 활동번호·활동명·버전을 넣고, 문서주소와 보고서상태를 시트에 남겨줘.
같은 내용으로 다시 누르면 기존 문서 링크를 사용하고 사본을 더 만들지 마.
결과가 바뀌면 새 버전으로 만들고 이전 보고서는 보존해줘.
문서가 생긴 뒤 중간에 멈춰도 활동번호와 버전으로 찾아 이어서 처리해줘.
생겼는지 불확실하면 더 만들지 말고 확인이 필요하다고 알려줘.
두 실행이 겹쳐도 같은 버전 문서를 중복으로 만들지 않게 해줘.
아직 PDF는 만들지 말고 기존 일정·자동 실행을 유지해 Code.gs 전체를 줘.
  1. Code.gs 전체를 바꾸고 저장한 뒤 시트를 새로고침해요.새로 필요한 Docs·Drive 권한은 메뉴 실행 때 확인해요.
  2. 결과를 입력한 줄에서 ‘선택 활동 보고서 만들기’를 눌러요.문서주소로 완성본을 열고 날짜·인원·한 일·느낀 점이 시트와 같은지 봐요.
  3. 원본과 결과 폴더도 열어봐요.원본에는 표시칸이 남고 완성본에는 값이 있어야 해요. 같은 내용으로 다시 실행해도 문서는 하나예요.

09 / KEEP A SHAREABLE COPY

같은 보고서를 PDF로 남기기

문서 생성과 PDF 저장은 서로 다른 단계예요. 어느 단계까지 성공했는지 구분해요.

지금 ‘선택 활동 보고서 만들기’ 메뉴가 Docs 다음에 PDF도 저장하도록 해줘.
완성한 문서의 저장을 마친 뒤 그 문서를 PDF로 바꿔 같은 결과 폴더에 넣어줘.
PDF 파일 이름에도 같은 활동번호와 버전을 넣어줘.
시트에 그 버전의 문서주소와 PDF주소를 구분해 남겨줘.
둘 다 확인된 뒤에만 ‘보고서 완료’로 표시해줘.
같은 내용을 다시 실행하면 같은 문서·PDF 링크를 돌려줘.
문서는 됐는데 PDF가 실패했다면 ‘PDF 재시도 필요’와 이유를 남겨줘.
다시 실행할 때 기존 문서는 재사용하고 없는 PDF 단계만 이어가줘.
PDF가 이미 생겼는지 불확실하면 같은 활동번호·버전으로 확인부터 해줘.
결과를 바꿔 새 문서 버전을 만들면 PDF도 그 버전과 맞춰 새로 만들어줘.
예전 버전이나 다른 사람의 파일은 삭제하지 마.
자동으로 공개 공유하거나 메일을 보내지 말고 담당자의 폴더에만 저장해줘.
기존 일정·자동 실행·문서 기능을 유지하고 Code.gs 전체를 줘.
  1. 코드 전체를 반영하고 같은 메뉴를 다시 실행해요.문서가 있는 활동은 그 문서를 재사용하고 PDF만 더하는지 봐요.
  2. PDF주소를 열어 첫 장부터 끝까지 읽어봐요.문자 깨짐·잘림이 없는지, 문서와 같은 버전·같은 내용인지 확인해요.
  3. 같은 메뉴를 다시 눌러 폴더의 파일 수를 비교해요.같은 버전이면 Docs 하나와 PDF 하나여야 해요. 링크만 나온 것을 완료로 보지 않아요.

참고: Google · 파일 형식 변환 ↗

직접 확인한 뒤 체크하세요.

10 / RUN IT AGAIN

다시 실행해도 믿을 수 있게

이 도구의 완성은 파일 하나가 나오는 것과 함께, 잘못된 입력과 반복 실행을 다루는 데 있어요.

잘못된 시간

종료를 시작보다 앞서게 입력한 새 연습 신청은 일정이 생기지 않고 이유가 남아야 해요.

빈 활동 결과

결과가 빈 줄은 보고서를 만들지 않아야 해요. 인원 0은 빈칸과 구분해요.

결과 수정

한 일을 고쳐 보고서를 만들면 새 버전과 같은 버전 PDF가 생기고 옛 버전은 남아야 해요.

트리거

폼 제출 같은 사건이나 정해진 시간에 작업을 시작해요.

서비스 연동

Apps Script가 Calendar·Docs·Drive 기능을 호출해요.

템플릿·재실행

양식에 값을 채우고, 활동번호·버전으로 중복을 막아요.

같은 작업을 다시 실행해도 이미 끝난 일을 중복하지 않는 성질을 멱등성이라고 해요. 문서 완료·PDF 실패처럼 일부만 된 상태를 남기면 필요한 단계부터 복구할 수 있어요.

지금 잘되는 동아리 자동 비서를 다음에도 이어서 만들고 싶어.
현재 Code.gs 전체를 생략 없이 줘. 새 기능은 넣지 마.
네 가지 설정 이름과 무엇을 넣는지 정리해줘.
메뉴 실행과 폼 제출 자동 실행을 각각 시험하는 방법을 알려줘.
설치된 트리거를 어디에서 확인하고, 수업이 끝나면 어떻게 중지하는지 알려줘.
일정·문서·PDF의 확인 결과를 내가 적을 빈칸도 만들어줘.
  1. v1 일정 메뉴, v2 제출 자동화, v3 보고서·PDF를 Docs에 보관해요.실제로 실행한 Code.gs 전체와 결과를 남겨요. 설정값은 개인 문서에서 관리해요.
  2. 연습을 마치면 이 프로젝트의 트리거만 삭제해요.Apps Script → 트리거 → 해당 항목 메뉴 → 삭제. 수업용 자동 실행을 중지하는 것이고 기존 일정·파일은 남아요.
  3. 친구에게 신청 한 건이 어떻게 보고서가 되는지 설명해요.파일을 보여줄 때에는 필요한 사람에게만 보기 권한을 정해요. 공개 게시와 메일 발송은 이번 기능에 넣지 않아요.

계정 주소나 개인 자료 대신 배운 점을 적어요.

OPTIONAL / A CLOCK CAN START IT

선택 · 일정이 빠진 신청 주기적으로 확인

기본 흐름을 완성한 뒤에만 추가해요. 시간 기반 트리거도 담당자 한 명이 관리합니다.

현재 동아리 도우미에 시간 기반 점검을 선택 기능으로 더하고 싶어.
함수 이름은 processPendingActivities로 해줘.
‘신청’에서 일정ID가 없고 상태가 빈칸 또는 ‘미등록’인 활동만 처리해줘.
‘오류’나 ‘확인 필요’, 이미 등록된 활동은 자동으로 재시도하지 마.
앞에서 만든 검증·중복 방지·일정 등록 기능을 그대로 사용해줘.
선택한 셀이나 팝업에 의존하지 말고 상태와 오류를 시트에 남겨줘.
기존 행의 활동번호는 유지하고, 한 번에 최대 10건만 처리해줘.
보고서와 PDF는 자동으로 만들지 말고 트리거도 자동 설치하지 마.
기존 기능을 유지한 Code.gs 전체와 시간 기반 트리거 설정 방법을 줘.
  1. 코드를 반영한 뒤 processPendingActivities를 먼저 수동 실행해요.실습 중인 제출 트리거를 잠시 삭제하고 새 폼 신청 한 건을 넣으면 미등록 상태를 준비할 수 있어요.
  2. 트리거 추가에서 시간 기반 → 분 단위 → 10분 간격을 선택해요.설치 뒤 새 폼 신청을 한 건 더 넣어요. 정확한 초 단위 실행은 아니므로 실행 목록에서 확인해요.
  3. 확인이 끝나면 시간 기반 트리거를 삭제해요.계속 운영할 때만 제출 트리거 하나를 다시 설치해요. 두 방식의 차이를 기록합니다.
