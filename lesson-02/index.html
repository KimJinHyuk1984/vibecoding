02 / ASK FIRST

친구들이 가고 싶은 부스부터

1회의 게임·시트는 보관하고, 새 AI 채팅과 새 설문·시트로 시작해요.

  1. 학교에서 안내한 AI 채팅을 새로 열어요.축제 앱은 같은 채팅에서 이어갑니다. 코드는 줄을 고치지 않고 전체를 옮겨요.
  2. Docs에 ‘2회_축제 운영 서비스’를 만들어요.설문 주소·새 시트 주소·앱 주소와 잘되는 버전을 보관해요.
  3. Forms에 빈 설문을 만들어요.제목은 ‘우리 학교 축제 선호도’. 실습에서는 실명·학번·연락처를 받지 않아요.

06 / CHANGE WITHOUT LOSING

취소하면 자리가 다시 열려요

기록을 없애지 않고 상태를 바꿔요. 별명만으로 다른 사람의 예약을 취소하지 않게 해요.

지금 잘되는 축제 앱에 예약 취소 기능을 더해줘.
예약번호와 취소용 확인문자를 모두 입력하고 ‘취소하기’를 누르게 해줘.
직전에 한 번 더 확인하고 두 정보가 맞을 때만 처리해줘.
별명만으로 취소하거나 다른 사람의 확인문자를 볼 수 있으면 안 돼.
줄은 지우지 말고 ‘취소’ 상태로 바꾸고 취소 시각을 남겨줘.
남은 자리 계산에서는 취소한 예약을 빼줘.
같은 예약을 두 번 취소해도 자리는 한 번만 늘어나야 해.
신청과 취소가 동시에 들어와도 정원과 자리가 정확해야 해.
실패하거나 두 정보가 안 맞으면 완료라고 표시하지 마.
취소 후 현황을 다시 읽고, 재조회 실패는 취소 실패와 구분해줘.
기존 기록을 유지하고 바뀐 Code.gs와 index.html 전체를 줘.
  1. 바뀐 파일 전체를 같은 이름의 파일에 붙이고 저장해요.둘 다 바뀌었다면 두 파일을 모두 교체해요.
  2. 배포 → 배포 관리 → 연필 → 새 버전 → 배포.코드 저장만으로 기존 앱 주소가 바뀌지는 않아요.
  3. 기존 /exec 주소를 새로고침하고 취소해요.줄은 남고 상태는 ‘취소’, 남은 자리는 정확히 1명 늘어나는지 봐요.

참고: Google · 배포 버전 갱신 ↗

08 / TURN RECORDS INTO INFORMATION

관심과 예약을 한눈에 비교해요

새 앱 대신 지금 화면에 운영 현황을 더해요. 명단 대신 집계 숫자를 보여줍니다.

지금 축제 앱 아래에 ‘축제 현황’을 추가해줘.
같은 시트의 ‘설문 응답’ 탭에서 ‘가고 싶은 부스’ 답을 읽어줘.
세 부스 이름과 일치하는 답만 각 부스의 관심 표로 세줘.
현재 ‘예약’ 상태만 세고 취소한 건은 활성 예약에서 빼줘.
부스마다 관심 표 수, 활성 예약 수, 정원, 남은 자리를 보여줘.
관심 비율은 유효한 설문 전체, 예약률은 해당 부스 정원이 기준이야.
둘을 구분한 막대그래프와 정확한 숫자를 같이 보여줘.
관심 순위와 예약 수 순위는 따로, 동점은 같은 순위로 보여줘.
설문이 비면 0과 ‘아직 응답이 없어요’, 탭·질문이 없으면 점검 안내를 보여줘.
불러오기 실패를 0건으로 숨기지 말고 재시도 버튼을 보여줘.
처음 열 때, 신청·취소 후, 현황 새로고침 때 갱신해줘.
공개 화면에는 집계만 보내고 별명·예약번호·확인문자는 보내지 마.
새 라이브러리 없이 기존 기능을 유지해 바뀐 파일 전체를 줘.

관심 비율

설문 10표 중 방탈출 5표라면 50%. 관심 조사 결과예요.

예약률

정원 2명 중 활성 예약 1명이면 50%. 실제 자리가 찬 정도예요.

남은 자리

정원 2명 − 활성 예약 1명 = 1명. 관심 표는 빼지 않아요.

기술 이름은 집계·필터·정렬·시각화예요. 응답이 0개일 때도 나눗셈 오류 없이 표시해야 해요.

  1. 고친 파일을 붙이고 새 버전을 배포해요.기존 예약 앱 주소를 계속 사용해요.
  2. 설문에서 부스별 표를 세고 화면과 비교해요.설문에 새 응답을 제출한 뒤 현황 새로고침을 눌러요.
  3. 활성 예약 수와 취소 전후 숫자를 비교해요.취소하면 예약은 줄고 관심 표는 그대로예요. 동점은 같은 순위여야 해요.

09 / WHAT HAPPENS BEHIND THE BUTTON

버튼 뒤에서 오가는 부탁과 결과

기술 이름을 외우기보다 화면·서버·시트 중 누가 무엇을 하는지 설명해봐요.

화면 → Apps Script → 스프레드시트 → 화면

화면이 서버에 “이 부스를 예약해줘”라고 부탁해요. Apps Script HTML 화면에서는 google.script.run이라는 통로를 사용할 수 있어요.

이것은 내 서버로 보내는 호출이에요. 다른 서비스의 주소에 GET·POST로 요청하는 외부 API 호출은 5회에서 확장합니다.

참고: Google · 화면에서 서버 호출 ↗

요청

별명·부스와 같은 신청을 구분할 정보를 보내요.

처리

서버가 입력·정원을 확인하고 시트에 기록해요.

응답

성공·마감·오류를 안내하고 현황을 다시 읽어요.

비동기 처리에서는 요청을 보낸 뒤 결과가 오면 후속 작업을 해요. “예약 확인 중”과 실패 안내도 앱의 기능입니다.

10 / FINISH THE SERVICE

친구가 쓰는 모습을 보고 완성하기

예약과 대시보드가 같은 시트의 기록을 보여주면 기본 완성입니다.

직접 확인한 뒤 체크하세요.

지금 잘되는 축제 운영 서비스를 다음에도 이어서 만들고 싶어.
실제로 사용하는 Code.gs와 index.html 전체를 파일별로 나눠서 줘.
새 기능 없이 설문·예약·취소·현황이 이어지는 모습을 유지해줘.
필요한 탭·설정 이름과 새 버전 배포 순서를 알려줘.
관심 표와 활성 예약 수를 비교할 확인 항목도 짧게 정리해줘.
결과는 지어내지 말고 내가 기록할 빈칸으로 남겨줘.

v1 · 화면 연습아직 실제 예약 아님

v2 · 실제 예약시트에 남는 한 줄

v3 · 축제 운영취소·정원·집계까지

실제로 실행한 두 파일을 Apps Script에서 복사해 Docs에 보관해요. 설문·시트·앱 주소도 구분해 적어요. 친구에게는 설문 응답자 링크와 예약 앱 링크를 안내해요.

개인정보·예약번호·확인문자 대신 배운 점을 적어요.

OPTIONAL / AFTER THE BASIC SERVICE

완성한 뒤 한 가지만 더하기

수정 전에 v3를 보관하고 같은 데이터로 원하는 화면을 더해요.

완성한 축제 앱에서 부스를 더 쉽게 찾고 싶어.
부스 이름 검색과 ‘예약 가능한 부스만 보기’를 넣어줘.
기본 순서, 관심 표 많은 순, 남은 자리 많은 순으로 정렬하게 해줘.

검색·정렬로 저장된 기록이나 전체 집계 숫자를 바꾸지 마.
같은 숫자인 부스도 빠지지 않게 해줘.
기존 예약·취소를 유지하고 바뀐 파일 전체를 줘.

조건을 초기화하면 세 부스가 다시 보이나요? 검색한 상태에서도 예약·취소 후 자리와 현황이 맞아야 해요.

정원 변경·시간대 추가는 규칙을 다시 설계하는 다음 도전이에요. 기본 완성 뒤 선생님과 범위를 정해요.
