02 / SAME RULES, NEW LOOK · 10 MIN

모양이 바뀌면 어떤 게임으로 보이나요?

한 칸 올라간 뒤 테마 버튼을 바꿔보세요. 바뀌는 것과 그대로인 것을 하나씩 찾습니다.

기본 계단 → 우주 탐험 → 도서관 탐험

제목·색·계단 모양은 바뀌어도 ← 방향 전환, → 올라가기 규칙은 같습니다. 체험이 열리지 않으면 바꾸고 싶은 제목과 분위기를 적어보세요.

LOOK

보이는 것을 바꾸기

제목, 색, 캐릭터, 계단 모양.
같은 동작도 다른 분위기로 보여요.

RULE

일어나는 일을 바꾸기

20칸에 도착하면 성공.
끝없이 오르던 게임에 목적지가 생겨요.

지금 체험은 디자인만 바뀝니다. 여러분의 게임에도 디자인을 먼저, 규칙은 그다음에 적용해요.

우주 탐험

별을 향해 오르는 탐험가. 어두운 배경, 밝은 계단.

도서관 탐험

책장을 오르는 작은 사서. 책 모양 계단, 따뜻한 색.

내가 만든 세계

학교 옥상, 바닷속, 간식 나라… 제목과 분위기를 정해보세요.

체험 예제는 선생님이 준비한 화면입니다. AI로 만들 결과의 모양이 똑같을 필요는 없어요.

03 / WRITE THE BRIEF · 15 MIN

“예쁘게”를 확인할 수 있는 말로

원하는 결과를 적은 약속을 요구사항이라고 해요. 먼저 Docs에 내 게임 설계 메모를 만듭니다.

“우주 느낌으로 예쁘고 편하게 바꿔줘.”

“제목은 별을 향해. 어두운 배경 위에 밝은 계단을 두고, 화면 아래에는 방향 전환과 올라가기 버튼을 나란히 배치해줘.”

친구가 화면을 보고 됐는지, 안 됐는지 판단할 수 있으면 좋은 출발이에요.

누가 사용해?

쉬는 시간에 노트북이나 휴대폰으로 게임할 친구.

무엇을 바꿔?

내 제목·세계관, 화면 배치, 20칸 도착 모드.

무엇을 지켜?

← 방향 전환·→ 올라가기. 한 칸은 1점. 다시 시작 가능.

내 게임 제목과 분위기 두 가지를 Docs에 적고, 다음 프롬프트의 [대괄호]를 바꿉니다.

맨 위 내 게임 제목 + 모드 선택

그 아래 오른 칸 수 + 바라보는 방향

가운데 캐릭터 + 다음 계단

맨 아래 ← 방향 전환 / → 올라가기 / 다시 시작

그림을 잘 그릴 필요 없어요. 무엇을 어디에 놓을지 전달하면 됩니다. 모드 선택은 규칙 추가 단계에서 만들어요.

게임을 바꾸기 전에 아래 요구사항을 정리해줘. 아직 코드는 수정하지 마.
사용자: 쉬는 시간에 노트북이나 휴대폰으로 게임하는 고등학생
제목: [내 제목, 예: 별을 향해]
분위기: [색과 모양 두 가지, 예: 어두운 배경, 밝고 둥근 계단]
배치: 위에 제목·점수·방향, 가운데 게임, 아래에 조작 버튼
유지: ← 방향 전환, → 올라가기, 한 칸 1점, 다시 시작
나중에 추가할 규칙: 시작 전에 고르는 ‘끝없이’와 ‘20칸 도착’ 모드
‘끝없이’는 기존대로, ‘20칸 도착’은 20칸에 도착하면 성공이야.
요구사항을 ‘지금 디자인 변경 / 다음 규칙 추가 / 유지’로 나눠줘.
각 항목 옆에 내가 직접 확인할 방법을 하나씩 써줘.

04 / DESIGN FIRST · 20 MIN

내가 정한 화면으로 바꾸기

AI가 정리한 요구사항을 읽고, 내가 쓴 내용과 맞는지 먼저 확인합니다. 맞으면 같은 채팅에서 이어갑니다.

방금 정리한 요구사항 중 ‘지금 디자인 변경’만 적용해줘.
내가 정한 제목, 색과 모양, 화면 배치를 반영해줘.
캐릭터는 직접 만든 간단한 도형으로 표현해줘.
점수와 방향 안내를 크게 쓰고 배경과 글자가 뚜렷이 구분되게 해줘.
375px 화면에서도 다음 계단과 조작 버튼이 잘 보이게 해줘.
← 방향 전환·→ 올라가기 규칙과 기존 기록 기능은 유지해줘.
모드 선택과 20칸 도착 규칙은 아직 추가하지 마.
외부 라이브러리·이미지·API 없이 단일 HTML로 실행되게 유지해줘.

직접 확인한 뒤 체크하세요.

한 번에 한 문장으로 고쳐보세요.

“점수 글씨가 배경에 묻혀. 점수 글씨와 배경의 밝기 차이를 크게 해줘. 나머지는 유지해줘.”

화면 캡처를 첨부할 수 있다면 어느 부분인지 함께 보여줍니다. 요청한 부분을 고친 뒤, 조작도 다시 확인해요.

BREAK · 10 MIN

작동하는 디자인을 저장하고 쉬어요

첫 번째 변화, 보관 완료.

현재 전체 HTML 코드를 Docs의 ‘v2 · 디자인’ 아래에 복사하고 화면도 캡처하세요. 코드가 일부만 보이면 마지막의 전체 코드 보관 프롬프트를 먼저 써도 됩니다.

쉬고 돌아오면 이 버전에 ‘20칸 도착’이라는 규칙을 더해요.

05 / ADD ONE RULE · 20 MIN

끝없이 오르기 vs 20칸에 도착하기

같은 게임에 두 가지 모드를 넣습니다. 모드는 시작 전에 고르고, 진행 중에는 바꾸지 않습니다.

ENDLESS

끝없이

20칸을 지나도 계속 올라가요.
계단과 방향이 다르면 게임이 끝나요.

GOAL

20칸 도착

19칸에서 한 칸 더 오르면 성공해요.
20칸 이후에는 이동과 점수가 멈춰요.

두 모드 모두 제한 시간은 없어요. 조건: 20칸 도착 모드에서 20칸 도달 → 결과: 성공 표시 후 멈춤.

지금 디자인을 유지하며 ‘끝없이’와 ‘20칸 도착’ 모드를 추가해줘.
1. 기본 선택은 ‘끝없이’. 시작 전과 종료 후에만 모드를 바꾸게 해줘.
2. ‘끝없이’는 기존대로 계속 오르고, ‘20칸 도착’은 20칸이면 성공이야.
3. 도착 모드는 현재 칸 수와 목표 20칸을 함께 보여줘.
4. 20번째 칸을 밟는 즉시 ‘도착!’을 표시하고 이동·점수를 멈춰줘.
5. 두 모드 모두 다음 계단과 다른 방향으로 오르면 실패로 끝내줘.
6. 성공·실패 후에는 방향 전환이나 올라가기를 눌러도 변하지 않게 해줘.
7. 다시 시작하면 선택한 모드를 유지하고 0칸·처음 위치·오른쪽 방향으로 돌려줘.
8. 진행 중 모드를 바꾸려 하면 ‘게임 종료 후 바꿀 수 있어요’라고 알려줘.
기존 ← 방향 전환·→ 올라가기, 디자인, 기록 기능은 유지해줘.
제한 시간과 외부 연결 없이 단일 HTML로 실행되게 해줘.
  1. 시작 전모드 선택 가능
  2. 진행 중조작 가능
    모드 변경 불가
  3. 성공 / 실패이동·점수 멈춤
    모드 선택 가능
  4. 다시 시작선택한 모드 유지
    0칸부터 새 판

이런 현재 상황을 상태라고 불러요. 상태에 따라 같은 버튼도 할 수 있는 일이 달라집니다.

20칸 도착 동작을 확인하는 예제

←로 방향을 맞추고 →로 한 칸씩 오릅니다. 20칸이면 성공하고 멈춥니다. 이 예제는 도착 모드만 체험합니다. 여러분의 게임에는 두 모드가 모두 있어야 해요.

06 / PROVE IT · 20 MIN

잘 되는 순간과 틀리기 쉬운 순간

친구와 역할을 바꿉니다. 한 명은 조작하고, 한 명은 실제 결과를 Docs에 적어요. 예상과 다르면 수정 프롬프트를 사용합니다.

① 도착 모드, 19 → 20칸

19칸에는 진행 중. 올바른 방향으로 한 칸 더 오르면 ‘도착!’이 나오고 20칸에서 멈춰야 해요.

② 성공한 뒤 ←, → 누르기

위치·점수·방향이 그대로여야 해요. 21칸이 되면 수정이 필요해요.

③ 끝없이 모드, 20 → 21칸

성공으로 끝나지 않고 계속 올라가야 해요. 두 모드의 차이를 확인합니다.

④ 계단과 다른 방향으로 올라가기

두 모드 모두 실패로 끝나야 해요. 이후 입력으로 점수가 늘면 안 돼요.

⑤ 진행 중 모드 바꾸기

안내만 나오고 모드·점수·위치가 그대로여야 해요.

⑥ 다시 시작 / 종료 후 모드 변경

선택한 모드로 0칸·시작 위치·오른쪽 방향에서 시작해야 해요. 터치 버튼도 확인합니다.

내 게임에서 테스트 결과가 요구사항과 달라. 원인을 찾고 고쳐줘.
선택한 모드: [예: 20칸 도착]
시작 상황: [예: 19칸, 오른쪽을 보고 있고 다음 계단도 오른쪽]
내 행동: [예: →를 한 번 눌러 20칸에 도착한 뒤 한 번 더 눌렀어]
실제 결과: [예: 21칸으로 올라갔어]
기대한 결과: [예: 20칸에 도착하면 성공으로 끝나고 더 움직이지 않아야 해]
오류 메시지: [있으면 그대로, 없으면 ‘없음’]
대괄호는 내가 겪은 상황으로 바꿔서 보낼게.
이 문제와 관련된 부분만 수정하고 디자인과 조작은 유지해줘.
고친 이유와 두 모드에서 다시 확인할 행동을 알려줘.
현재 코드는 수정하지 말고 실제 코드에 근거해 설명해줘.
1. 선택한 모드와 시작 전·진행 중·성공·실패 상태를 어디에 기억해?
2. 20칸 도착 조건은 언제 확인하고, 끝없이 모드에는 왜 적용되지 않아?
3. 성공한 뒤 버튼을 눌러도 점수가 늘지 않게 막는 부분은 어디야?
각각 실제 코드의 짧은 부분과 쉬운 설명을 함께 보여줘.
설명한 내용이 맞는지 실행으로 확인할 방법도 알려줘.

직접 확인한 뒤 체크하세요.
