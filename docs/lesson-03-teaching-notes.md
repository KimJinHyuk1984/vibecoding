# 3회 운영 메모 — 우리 반 게임 랭킹

> 통합 이전 수업의 운영 이력입니다. 현재 수업은 [통합 1회 운영 메모](lesson-01-teaching-notes.md)를 기준으로 합니다.

## 목표와 진행 방식

학생이 2회에 만든 게임 HTML을 AI에게 제공하고, Google Sheets에 기록을 저장할 Apps Script 코드까지 직접 요청한다. 같은 채팅에서 생성한 Code.gs와 index.html을 한 프로젝트에 넣어 실행한다. 학생마다 함수나 열 이름은 달라도 된다. 성공 기준은 자기 게임의 기록이 실제 시트에 저장되고 친구와 같은 랭킹을 보는 것이다.

교사 코드 배포와 연습 숫자 전용 화면을 거치는 과정은 사용하지 않는다. 출발점은 학생의 게임 HTML이며, 연결할 Code.gs도 학생이 AI에게 요청한 결과물이다. 코드 해석, 일부 줄 찾기, 함수 이름 암기를 요구하지 않는다. 교사는 복사·붙여넣기, 설정 화면, 배포·권한 확인을 돕는다.

2인 1조로 제작과 확인 역할을 교대한다. 팀 대표 계정의 빈 시트와 Apps Script 프로젝트 하나를 사용한다. 친구와 비교할 때는 같은 팀의 게임 주소를 열어야 하며, 반 전체 비교도 완성한 앱 중 하나로 모여서 한다.

## 학생이 코드 내용을 읽지 않고 진행하는 방법

- PROMPT 01에 자기 게임 HTML 전체를 함께 준다. 같은 대화에서 02와 03을 이어가야 두 파일이 서로 맞는다. 새 대화에서는 실제 사용 중인 두 파일 전체를 다시 제공한다.
- Code.gs는 저장·불러오기와 게임 화면 열기를 맡는다. index.html은 학생의 게임에 저장 버튼을 더한 전체 HTML이다. HTML 파일명은 소문자 index로 통일한다.
- AI 답변은 파일별 코드 블록의 복사 버튼으로 가져와 해당 파일 전체를 교체한다. 일부만 제시하면 “코드 줄을 찾지 않게 파일 전체를 줘”라고 추가 요청한다.
- 시트 주소는 코드에 직접 넣지 않는다. 프로젝트 설정의 스크립트 속성 이름을 `SHEET_URL`로 하고, 값에는 본인 시트 주소 전체를 붙인다. 주소 일부를 추출하거나 AI에게 실제 시트 주소를 전달할 필요가 없다.
- ‘기록’ 탭과 열 제목은 처음 저장할 때 AI 코드가 만들도록 요청한다. 별도의 교사 준비 함수나 고정된 열 순서는 사용하지 않는다.
- 개선으로 둘 중 어느 파일이 바뀌었는지 확인한다. 둘 다 바뀌면 둘 다 반영하고 기존 배포를 새 버전으로 업데이트한다.
- ‘첫 저장 성공’은 게임을 플레이한 실제 칸 수가 시트의 한 줄과 일치하는 것이다. 랭킹을 만들기 전에는 시트에서 확인하고, 랭킹 완성 뒤에는 다른 학생 화면에서도 확인한다.

## 수업 전 실제 계정으로 확인할 것

교사 계정과 학생 계정에서 Sheets 확장 프로그램, Apps Script, 스크립트 속성 설정, 웹앱 배포 접근을 확인한다. 교사는 학생용 프롬프트를 자신의 게임 HTML에 실제로 적용해 두 파일을 생성하고 끝까지 실행해본다. 생성된 코드를 학생에게 공통 정답으로 나눠주지 않는다.

배포 실행 주체는 ‘나’, 접근 범위는 같은 학교 조직으로 정한다. 학교 내부 옵션이 없거나 관리자 정책으로 차단되면 선생님과 허용된 계정·기기를 확인하고 짝 활동으로 역할을 나눈다. 권한 경고를 무조건 넘기거나 공개 범위를 넓혀 우회하지 않는다. 첫 실행의 인증·배포에 시간이 더 걸릴 수 있으므로 20분을 배정했다.

실제 사전 확인 순서: 게임 HTML 제공 → Code.gs 생성 → index.html 연결 → 두 파일 설치 → SHEET_URL 설정 → 웹앱 배포 → 자기 게임 한 판 저장 → 시트에서 확인 → 랭킹 추가·재배포 → 다른 학생 계정으로 같은 주소 접속.

생성형 AI의 답변은 매번 달라진다. 웹 강의 페이지의 복사·표시 검증만으로 생성 앱의 저장 성공을 보증할 수 없다. 현재 저장소 작업에서는 실제 Google 계정에 배포하거나 Sheets에 기록하지 않았다.

## 교사용 기술 확인 지점

다음 항목은 교사가 사전 실행에서 확인하는 참고다. 학생에게 API 이름이나 구현 방식을 외우게 하지 않는다.

- 웹앱은 Code.gs의 doGet에서 소문자 index HTML을 반환해야 한다. 두 파일은 같은 Apps Script 프로젝트 안에서 실행한다. 내려받은 HTML이나 AI 미리보기에서 실제 시트 연결을 검사하지 않는다.
- 시트 연결에는 Script Properties의 SHEET_URL을 읽고 SpreadsheetApp.openByUrl 등으로 문서를 명시적으로 연다. 웹앱 실행에서 활성 스프레드시트에 의존하지 않도록 확인한다.
- HTML과 서버 간 호출 이름·인자·반환 값은 AI가 생성한 두 파일 사이에서 일치해야 한다. 고정된 교사 함수명이나 열 구조는 없다.
- 저장할 판을 구분하고, 같은 내용의 재시도에 같은 판 식별값을 유지해야 한다. 동시 저장에서 중복 확인·추가가 충돌하지 않는지도 확인한다. 학습용 표현은 “한 판은 한 줄, 친구와 동시에 눌러도 각각 한 줄”이다.
- 별명은 한글·영문·숫자 2~12자, 점수는 0~10000의 정수, 저장 대상은 끝없이 놀이로 제한하도록 요청했다. Code.gs에서도 확인되어야 한다. 화면은 입력 문자열을 실행 가능한 HTML로 해석하지 않도록 확인한다.
- 날짜 값은 서버에서 기록하고, 화면에 반환할 때는 전달 가능한 문자열 등으로 바꿔야 한다. 저장 성공과 랭킹 불러오기 성공은 구분한다.
- 별명별 최고 기록 10명, 동점 순위 1·1·3을 확인한다. 동점 안의 표시 순서는 고정하지 않는다. 같은 별명은 같은 사람으로 묶이므로 교실에서는 서로 다른 별명을 쓴다.
- 이 앱은 입력 검증을 해도 실제 플레이 점수를 증명하지 않는다. 부정행위를 판별하는 공인 대회용 서비스로 설명하지 않는다.
- 표 제목과 저장 데이터가 어긋나거나 기존 행이 지워지는지 확인한다. 수정 시 기존 기록을 유지하도록 요청하고, 문제 해결을 위해 시트 전체를 지우게 하지 않는다.

## 진도 차이와 발표

기본 27개 조각, 보충 포함 30개다. 보충 3개는 일부 답변을 받았을 때의 요청, /dev와 /exec 구분, 친구와 더 시험하는 프롬프트 07이다. 웹 페이지에서는 모두 볼 수 있다.

늦는 팀은 랭킹 꾸미기보다 자기 게임에서 시트 한 줄 저장을 먼저 완성한다. 실패 화면과 오류 문구를 PROMPT 06에 넣고, 실제 설치한 두 파일 전체를 함께 전달한다. 시간이 부족해 짝의 프로젝트를 함께 확인한 경우에는 자신의 앱 연결까지 끝냈다고 체크하지 않는다. 빠른 팀은 동시 저장·동점·낮은 기록을 더 시험한다.
