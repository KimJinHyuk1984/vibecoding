# 6회 · 내 아이디어를 실제 서비스로

`plan2.md`의 마지막 프로젝트를 구현했다. 1~5회에서 배운 기능 중 필요한 것을 고르고, 스스로 정한 문제를 해결하는 작은 서비스를 만든다. 한 프로젝트를 2시간 안에 끝내는 구성은 아니다. 첫 동작 완성 → 세 기능 연결 → 친구 관찰과 개선의 도달점을 기준으로 나누어 운영한다.

## 목표와 진행

1. 출발 아이디어를 비교하고 기능 조합 보드에서 최대 세 기능을 고른다.
2. Docs에 사용자·불편·세 기능·성공 장면·미룰 일을 적고 AI와 계획을 줄인다.
3. 새 작업 공간과 연습 자료를 준비하고 `index.html` 전체로 화면을 확인한다.
4. 첫 기능의 `Code.gs` 전체를 학생이 AI에 요청한다. 화면과 서버를 연결하고 실제 결과를 대조한다. 나머지 기능에도 반복한다.
5. 정상·빈 입력·중복·실패·다른 계정 접근 중 해당하는 것을 시험하고, 재현 순서로 오류를 고친다.
6. 친구에게 사용법 대신 미션을 주고 관찰한다. 실제 행동과 제작자의 해석을 나눠 적는다.
7. 중요한 문제 하나를 개선하고 같은 미션으로 비교한다. 최종 파일·배포 버전·사용 설명서·남은 문제를 남긴다.

교사가 완성 코드를 제공하지 않는다. 8개 기본 프롬프트와 다음 아이디어를 위한 선택 프롬프트 1개는 클릭 복사 방식이다. 대괄호를 채우고, 코드 조각 대신 현재 파일 전체를 전달하고 수정된 전체 파일을 받는다. 오류 수정은 선택 도움말이 아닌 본 과정이다. 실제 오류가 없으면 고장 사례를 지어내지 말고 테스트 결과를 확인한 뒤 친구 테스트로 간다.

## 기능 조합 예시

| 문제 | 첫 세 기능 | 연결할 회차 |
| --- | --- | --- |
| 학교 물품 대여 | 검색·신청/정원·담당자 반납 | 2회 예약, 4회 검색·상태 |
| 동아리 작품 전시관 | 사진·검색·반응 통계 | 4회 파일, 2회 통계 |
| 학급 행사 도우미 | 설문·일정·결과 보고서 | 2회 Forms, 3회 자동화 |

조합은 출발점이다. 전시관의 반응 입력, 대여 기간·취소 규칙, 행사 하나와 설문 응답의 관계는 기획에서 정해야 한다. 앞선 코드를 단순 연결하면 서로 다른 열 구조·식별자·권한·함수 이름이 충돌할 수 있다. 선택 기능의 동작과 보호 조건을 참고해 하나의 기획으로 다시 요청한다. 모든 기술을 사용하게 평가하지 않는다.

## 기술 지도 포인트

- HTML은 화면, Apps Script는 서버 동작, Sheets·Drive·Calendar는 자료와 작업 대상이다. `google.script.run` 연결 후에는 로컬 HTML이 아니라 웹 앱 `/exec`에서 확인한다.
- 설정은 Script Properties에 두고 필요한 자료만 만든다. 신규 프로젝트와 연습 자료로 시작해 기존 수업 결과를 보존한다. 트리거가 필요한 경우에만 3회 구조를 적용한다.
- 예약/반환은 서버 측 수량 확인·동시성·중복 요청·담당자 권한을 다시 확인한다. 이름만으로 타인의 신청을 취소하거나 상태를 바꾸지 못하게 한다.
- 사진은 형식·크기·대상 폴더를 제한한다. Drive 파일이 비공개여도 소유자 권한 웹 앱이 사진을 전달하면 이용자에게 보인다.
- 자동화는 안정적인 신청 ID와 부분 실패 재시도를 유지한다. 보고서는 원본 템플릿을 보존한다. 행사 설문 응답을 모두 별도 일정으로 만들지 않도록 실제 규칙을 먼저 정한다.
- API는 고정된 공식 출처·서버 인증·날짜·오류·캐시 조건을 확인한다. 외부 AI는 5회의 이용 조건을 충족할 때만 사용한다. 이번 회차의 필수 기술이 아니다.
- 수정 파일 저장과 배포 버전 갱신은 다르다. 기존 배포를 새 버전으로 갱신하면 URL을 유지한다. 이전 버전 선택은 코드 실행 버전만 되돌리며 자료·속성·트리거를 자동 복원하지 않는다.
- 사용 후 유지할 담당자가 없다면 배포 보관처리·불필요한 트리거 삭제·외부 API 중지를 확인한다. 테스트 자료 정리는 실제 운영 자료와 구분해서 진행한다.

공식 배포·실행 계정 설명은 2026-10-05 확인한 [웹 앱 문서](https://developers.google.com/apps-script/guides/web), [배포 관리 문서](https://developers.google.com/apps-script/concepts/deployments)에 따른다. 실제 계정에 표시되는 접근 범위는 학교 정책에 따라 확인한다.

## 관찰과 평가

평가 자료는 기획의 성공 장면, 작동하는 실행 결과, 오류 재현·재시험 기록, 친구가 실제로 한 행동, 개선 전후 비교다. AI가 만든 설명·테스트 표만으로 통과 처리하지 않는다. 테스트 표는 행동 / 예상 / 실제 / 통과·수정 필요·미실행·해당 없음으로 적는다. 도움 후 완료는 혼자 완료와 구분한다. 같은 친구의 재시험에는 학습 효과가 있을 수 있다.

3분 시연에서는 문제와 핵심 동작, 고친 지점, 남은 문제를 보여준다. ‘무엇이든 즉시 완성’이 아니라 새로운 아이디어를 작게 나누고 필요한 조건을 확인하며 시작할 자신감을 목표로 한다.

## 웹 페이지와 실습의 구분

페이지의 기능 조합 보드는 로컬 UI 연습이다. 세 가지 예시·직접 선택·최대 세 기능 제한·해제·초기화·복습 링크를 제공하며 실제 앱 생성, 저장소 생성, Google 연결을 수행하지 않는다. 선택은 새로고침 시 초기화한다. 체크와 성찰 기록만 기존 공통 위젯의 브라우저 저장 기능을 사용하며 다른 기기에 자동 동기화하지 않는다.

학생별 생성 코드·Google 로그인·권한·실제 배포·친구 테스트는 수업에서 별도로 검증해야 한다. 이 저장소의 브라우저 검증은 강의 페이지와 로컬 위젯에 관한 것이다.
