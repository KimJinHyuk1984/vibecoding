# 3회 구현 및 검증 — 일하는 동아리 자동 비서

검증일: 2026-10-01

## 반영한 요청

사용자가 2회를 확인한 뒤 “다음 작업 하자.”라고 지시하여 plan2.md의 3회를 작성했다. 활동 신청에서 일정 생성, 실제 결과 기록, 보고서·PDF 저장까지 연결했다. 4회 본문은 작성하지 않았다.

이번 프로젝트는 Forms·Sheets를 입력·관리 화면으로 활용한다. 새 웹 앱을 배포하는 대신 시트에서 연 Apps Script에 AI가 만든 Code.gs 전체를 붙여 맞춤 메뉴를 만든다. 메뉴로 일정 등록을 먼저 확인하고 설치형 폼 제출 트리거로 확장한다. 원본 Docs 양식을 복사해 결과를 채우고 PDF로 저장하는 요청까지 이어진다.

- 12개 섹션, 프롬프트 9개(기본 7·선택 1·도움 1), 위젯 6개(체험 1·체크 4·제작 기록 1).
- 기본 발표 36개·보충 포함 40개. 긴 프롬프트 4개를 발표에서만 나누고 복사는 전문을 유지한다.
- 고유 활동번호, 중복 방지, 시간대, 실행 계정, 템플릿 치환, 버전, 일부 실패 후 재시도를 설명한다.
- 시트 셀 편집과 실제 폼 제출을 구분한다. 자동 실행에서 선택 셀이나 팝업을 사용하지 않도록 요청한다.
- 관심 있는 학생은 시간 기반 미등록 일정 점검을 선택한다. 수업 후 트리거 중지까지 안내한다.
- 허브 6개 프로젝트 중 1~3회만 공개하고 2회에서 3회로 연결했다. 이전 lesson-03 이동 페이지는 새 강의로 교체했다.

## 보존과 미실행 범위

변경 대상은 lesson-03/index.html, widgets.js·lecture.css의 3회 기능, data/site.js의 공개 상태, 2회 다음 링크, 허브 정적 안내, README와 작업 문서다. DESIGN.md·tokens.css·base.css·shared.js·instructor는 그대로다.

실제 Google 계정으로 Forms를 생성·제출하거나 권한을 승인하지 않았다. Calendar 일정·Docs 문서·PDF 생성, 학생별 AI 생성 Code.gs 실행도 미실행이다. 위 테스트는 강의 페이지와 로컬 모형의 검증이며 실제 서비스의 작동 보증이 아니다. 운영 메모의 실제 계정 시나리오로 사전 확인해야 한다.

3회 피드백을 받은 뒤 다음 회차로 진행한다. Git 커밋·푸시·외부 배포는 실행하지 않았다. 검증용 스크립트·캡처는 Git 제외 work-temp에 남겼다.
