# 1회 운영 메모

## 수업 목표

학생이 바이브코딩을 자신의 말로 설명하고, 무한의 계단 게임을 실행한 뒤 본인이 정한 변경을 하나 적용하며, 결과물을 보관한다.

## 진행

| 구간 | 분 | 교사의 확인 |
| --- | --- | --- |
| 소개 | 10 | 코드가 생성되며 결과 확인은 제작자의 역할임을 설명한다. |
| 체험 | 5 | 페이지의 체험 게임을 해보고 바꾸고 싶은 점 하나를 말하게 한다. |
| 준비 | 10 | 학교에서 허용한 계정으로 접속한다. Canvas 미리보기 여부를 확인한다. |
| 첫 제작 | 25 | 복사 버튼 사용 후 생성 완료를 기다리고 직접 한 판 실행한다. |
| 테스트 | 10 | ← 방향 전환, → 올라가기, 잘못된 방향, 재시작, 화면 버튼을 확인한다. |
| 휴식 | 10 | 작동하는 버전의 코드를 Docs에 보관한다. |
| 내 스타일 | 20 | 디자인·기록·작은 화면 중 하나를 고르고 변경 후 기존 동작도 확인한다. |
| 오류 해결 | 15 | 행동·실제 결과·기대 결과를 설명하게 한다. 잘 되는 학생은 원리 설명 프롬프트를 사용한다. |
| 저장·공유 | 15 | 옆 친구가 사용해보고 의견을 남긴다. Drive/Docs에 코드·화면·변경 이유를 보관한다. |
| 합계 | 120 | 휴식 포함 |

## 수업 전 준비

- 교사 계정만으로 확인하지 말고 실제 학생 계정의 Gemini 접근과 학교 정책을 확인한다.
- Canvas가 제공되지 않는 경우, 허용된 AI에서 단일 HTML을 생성한 뒤 학교 기기에 맞는 저장 방법을 안내한다.
- Windows 메모장 저장 방법은 페이지의 보충 안내에 있다. Chromebook 등에서는 학교에서 허용한 텍스트 편집 도구나 다운로드 방법을 준비한다.
- Docs는 코드 보관용이며 HTML 실행 환경이 아니다. 실행과 보관을 구분해서 안내한다.
- 모든 학생이 같은 모양의 게임을 얻을 필요는 없다. 테스트 항목을 만족하는지 확인한다.
- 문제가 생긴 학생은 ‘오류 수정 요청’으로 이동하고, 빠른 학생은 최근 기록 또는 모바일 기능을 추가한다.
- 첫 수업에는 AI API 연결, API 키 공유, 학생 정보 수집, 공개 링크 만들기를 요구하지 않는다.

## 무한의 계단 조작 안내

- 왼쪽 방향키(←): 제자리에서 바라보는 방향만 좌우로 전환한다. 점수는 늘지 않는다.
- 오른쪽 방향키(→): 바라보는 방향으로 한 칸 올라간다. 왼쪽을 보고 있을 때도 올라가는 키는 →다.
- 다음 계단과 바라보는 방향이 다르면 게임이 끝난다. 다시 시작하면 0칸·시작 위치·오른쪽 방향으로 돌아간다.
- 체험 예제는 제한 시간 없이 진행한다. 화면 버튼으로도 같은 조작을 할 수 있다.
- 게임을 시작하면 게임 영역에 키보드 초점이 놓인다. 발표 모드에서도 초점이 게임 안에 있으면 방향키는 게임을 조작한다. 다른 슬라이드로 이동하려면 게임 밖을 클릭하거나 Tab으로 초점을 옮긴다.
- 최고 기록은 현재 페이지를 연 동안 유지한다. 최근 5판 기록 기능은 학생이 선택하는 추가 미션이다.

## 도구 관련 참고

- [Google Canvas 도움말](https://support.google.com/gemini/answer/16047321?hl=ko): 코드·앱 생성과 미리보기. 일부 공유·AI 추가 기능에는 연령 제한이 있어 이번 수업의 필수 흐름에서 사용하지 않는다.
- [학교 계정의 Gemini 사용](https://support.google.com/gemini/answer/14620100?co=DASHER._Family%3DEducation&hl=ko): 학교 관리자 설정과 계정별 기능을 확인한다.

이 페이지의 무한의 계단 게임은 직접 작성한 로컬 체험 예제다. 학생이 Gemini에서 실제 생성한 결과라고 표시하지 않는다. 7개 프롬프트는 이 수업을 위해 새로 작성했으며 원본 코드 전재가 아니다.
