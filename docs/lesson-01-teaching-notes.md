# 통합 1회 운영 메모 — 내 게임을 우리 반 서비스로

## 목표와 전제

이전 1~3회를 하나의 프로젝트로 합쳤다. 학생은 코드를 읽지 못해도 원하는 모습을 설명하고, AI가 만든 파일 전체를 복사해 실행하며, 화면과 실제 기록으로 성공 여부를 판단한다. 게임 제작 → 자기 취향 반영 → 시트 저장 → 친구와 공유가 하나의 이야기로 이어진다.

수업 시간이나 분 단위 진도를 정하지 않는다. 아래 네 가지 결과를 직접 확인한 뒤 다음 단계로 진행한다. 교사 코드를 배포하지 않고, 학생의 게임 HTML을 바탕으로 저장용 Code.gs까지 학생이 AI에게 요청한다.

## 필수 진행 흐름

| 순서 | 진행 | 직접 확인할 결과 |
| --- | --- | --- |
| 소개·체험 | 바이브코딩 소개 후 무한의 계단 체험. 같은 게임을 친구와 써보고 싶다는 목표 제시 | ←는 방향만 바꾸고 →는 한 칸 오르는 규칙을 말할 수 있다 |
| 첫 게임 | PROMPT 01 → 미리보기 또는 HTML 파일 실행 | 시작·이동·실패·다시 시작이 된다. 확인 ① 체크 |
| 내 취향 | 테마 체험 → 제목·분위기를 바꾼 PROMPT 02 | 요청한 모습이 보이며 기존 조작은 유지된다. 확인 ②를 친구와 비교 |
| 기록장 준비 | 저장·읽기 체험, 빈 Sheet, Apps Script, 시트 주소 전체 준비 | 게임 화면·저장 담당 코드·시트의 역할을 구분한다 |
| 두 파일 연결 | 최신 게임 HTML 전체와 PROMPT 03 → Code.gs, 같은 채팅에서 04 → index.html | 파일별 전체 붙여넣기와 SHEET_URL 설정을 마친다 |
| 실제 저장 | 학교 내부 웹앱 배포 → 자기 게임 한 판 → 별명과 점수 저장 | 게임의 실제 점수가 시트 한 줄과 일치하고 새로고침 뒤에도 남는다. 확인 ③ 체크 |
| 친구와 공유 | PROMPT 05 → 바뀐 파일 교체 → 새 버전 배포 → 친구와 같은 주소 | 친구 기록·별명별 최고·동점·중복 저장을 확인한다. 확인 ④ 체크 |
| 보관·다음 아이디어 | PROMPT 06, 실제 파일과 주소·증거 보관, 다음 앱의 화면·저장할 내용·확인 결과 설명 | “무엇을 설명하고 어떻게 확인할지”를 새로운 아이디어에도 적용한다 |

기본 프롬프트는 01~06 여섯 개다. 오류가 생길 때 사용하는 도움 프롬프트와 선택 미션 A~C를 포함하면 복사 블록은 총 10개다. 필수 과정에서 20칸 도착 모드나 최근 5판 기록을 먼저 만들게 하지 않는다.

## 성공 지점과 진도 차이

학생이 AI의 완료 답변을 보고 체크하지 않게 한다. 한 명이 조작하고 다른 한 명이 예상과 실제를 비교한 뒤 역할을 바꾼다. 활동 중 쉬거나 다음 날 이어야 한다면 잘되는 버전을 보관한 지점에서 멈춘다. 첫 저장이 된 v3는 좋은 중간 도착점이다.

오류는 언제든 페이지의 도움 프롬프트를 사용한다. 학생은 누른 버튼·순서·실제로 보인 모습·원하는 결과를 적고 실제 사용한 전체 파일을 제공한다. 아직 Code.gs를 만들지 않았다면 게임 HTML만 준다. 코드 줄을 찾아 수정하게 하지 않는다.

빠른 학생도 시트 한 줄과 친구 랭킹 확인을 건너뛰지 않는다. 공유 랭킹까지 완성한 뒤 원하는 선택 미션 하나를 한다. 다른 팀의 파일을 섞거나 교사 예제 서버로 대체하지 않는다. 짝의 프로젝트를 같이 확인한 경우 자신의 프로젝트도 완성했다고 체크하지 않는다.

## 선택 미션의 범위

- A 최근 5판: 브라우저 화면 안의 최근 기록이다. 이 목록을 지워도 시트와 친구 랭킹은 유지되어야 한다. 새로고침 후 목록은 사라져도 된다.
- B 휴대폰 개선: 게임·별명 입력·저장·랭킹을 좁은 화면에서 확인한다. 한 번 터치에 한 번만 동작해야 한다.
- C 20칸 도착: 기본 끝없이 놀이를 유지하며 연습 모드를 추가한다. 20칸에서 멈추고 성공·실패 모두 시트와 랭킹에 저장하지 않는다. AI에게 두 파일을 함께 검토하게 하고 기존 끝없이 기록은 계속 저장되는지 확인한다.

선택 미션은 수정 전 버전 보관 → 한 가지 요청 → 바뀐 파일 교체 → 새 버전 배포 → 게임·저장·랭킹 재확인 순서다. 기본 발표에서는 선택 미션을 건너뛰며 웹 페이지에는 모두 보인다.

## 파일과 기록을 보관하는 방식

| 버전 | 보관할 내용 |
| --- | --- |
| v1 첫 게임 | 전체 HTML, 처음 실행한 화면 |
| v2 내 디자인 | 바꾼 전체 HTML, 바뀐 점과 이전 조작 확인 결과 |
| v3 첫 저장 | Code.gs와 index.html, 시트 주소·게임 주소, 저장된 한 줄 |
| v4 공유 랭킹 | 실제 실행한 두 파일, 친구가 확인한 결과, 수정한 문제 |

Docs는 보관 장소다. 처음에는 AI 미리보기나 로컬 HTML에서 실행하고, 시트 저장부터는 Apps Script의 배포한 게임 주소(/exec)를 사용한다. 다른 프로젝트로 복사하면 SHEET_URL 설정도 다시 넣어야 한다. 개인 Docs에 시트 주소와 게임 주소를 구분해 둔다.

## 교사의 사전 준비와 기술 확인

학교 계정에서 Gemini·Canvas 또는 허용된 AI 도구, Sheets, Apps Script, 스크립트 속성 설정, 웹앱 배포와 학생 간 접속을 확인한다. 실제 수업에 쓸 계정에서 프롬프트 01~06을 끝까지 실행해보고, 학생에게는 자기 결과물을 만드는 과정을 안내한다. 생성된 코드는 매번 달라지므로 강의 페이지 검증을 학생별 앱의 저장 성공으로 간주하지 않는다.

- 두 파일은 같은 Apps Script 프로젝트에 둔다. HTML 이름은 소문자 index, 저장 담당은 Code.gs다. 웹앱에서 index 화면이 열려야 한다.
- 학생은 프로젝트 설정의 스크립트 속성에 SHEET_URL이라는 이름과 시트 주소 전체를 넣는다. AI가 그 주소로 시트를 명시적으로 열도록 요청했다. 웹앱에서 활성 시트에 의존하지 않는지 교사가 확인한다.
- ‘기록’ 탭과 열 제목이 없으면 첫 저장 때 만들고 기존 기록은 지우지 않아야 한다. 고정된 교사 함수 이름이나 열 순서를 학생에게 요구하지 않는다.
- 별명 2~12자(한글·영문·숫자), 점수 0~10000의 정수, 같은 판 재시도와 동시 저장, 날짜 반환 형태, 화면과 서버 호출의 일치를 사전 확인한다. 함수 이름·자료 형식은 교사용 확인 사항이며 학생 프롬프트를 전문 용어로 바꾸지 않는다.
- 저장 성공과 랭킹 읽기 실패를 구분한다. 저장 중에는 새 판·별명 수정·연속 저장을 잠시 막고, 재시도는 같은 판과 내용으로 보낸다.
- 랭킹은 별명별 최고 10개, 동점 1·1·3이다. 실명·학번 대신 서로 다른 별명을 쓴다. 실제 플레이 점수를 증명하는 대회용 부정행위 방지 기능은 아니다.
- 배포 실행 주체는 ‘나’, 접근은 같은 학교 조직으로 정한다. 해당 옵션이 없거나 차단되면 학교에서 허용한 계정·기기를 확인한다. 권한 경고를 무조건 넘기거나 공개 범위를 넓혀 우회하지 않는다.
- 파일을 고쳤으면 기존 배포를 새 버전으로 갱신한다. 친구와 비교하려면 같은 /exec 주소를 열어야 한다. 팀마다 다른 주소는 서로 다른 시트와 랭킹이다.

## 페이지와 발표

본문은 11개 섹션이다. 기본 발표 29개, 보충 포함 37개 조각으로 구성했다. 보충은 로컬 HTML 실행 안내 1개, 선택 미션 5개, 도움 2개다. S 키로 포함할 수 있다. 네 가지 체험은 기본 계단, 디자인 테마, 저장·읽기, 선택 20칸 도착이다.

새 1회만 공개한다. 이전 4~13회 주제는 새 2~11회로 옮겨 목록에서 준비 중으로 표시한다. 이전 2·3회 주소는 통합 1회의 해당 위치로 이동하며, 향후 새 회차를 제작할 때 이 이동 안내를 교체한다. 다음 회차는 사용자 피드백 후 진행한다.

## 참고 및 검증 범위

저장 연결 절차는 기존 개편에서 확인한 [Google HTML 서비스](https://developers.google.com/apps-script/guides/html), [웹앱](https://developers.google.com/apps-script/guides/web), [스크립트 속성](https://developers.google.com/apps-script/guides/properties#manage_script_properties_manually), [배포 관리](https://developers.google.com/apps-script/concepts/deployments)를 따른다. 학교별 실제 접근 화면은 사전 확인 대상이다.

현재 작업에서는 실제 Gemini 생성 결과를 실행하거나 Google 계정에 로그인·배포·저장하지 않았다. 강의 페이지의 브라우저 검증은 [통합 검증 보고서](lesson-01-merged-verification.md)를 참고한다.
