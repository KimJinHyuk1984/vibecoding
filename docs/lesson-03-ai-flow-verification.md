# 3회 개편 검증 — 내 게임과 저장 코드를 AI에게 요청하기

> 통합 이전 시점의 검증 기록입니다. 현재 페이지 기준은 [통합 1회 검증](lesson-01-merged-verification.md)입니다.

검증일: 2026-10-01

## 사용자 피드백과 구현

사용자는 index.html을 학생이 만든 게임 HTML로 사용하고, 스프레드시트 저장용 Apps Script 코드도 학생이 직접 AI에게 요청하는 흐름을 원했다. 3회 본문, 프롬프트 8개, 진행 시간, 운영 메모, README와 작업 상태를 이 흐름으로 수정했다. 1~2회와 다음 회차는 변경하지 않았다.

현재 순서: 학생의 게임 HTML 제공 → Code.gs 전체 생성 요청 → 기존 게임에 저장 기능을 연결한 index.html 전체 요청 → 같은 Apps Script 프로젝트에 두 파일 붙여넣기 → 설정 화면에 시트 주소 입력 → 웹앱 배포 → 자기 게임의 실제 점수 저장 → 저장 안내·랭킹 개선 → 친구와 확인·보관.

Code.gs의 구체적인 함수명과 열 구조는 학생별 AI 답변이 정한다. 파일 이름과 설정 위치만 공통으로 안내한다. 학생이 코드 속 연결값을 수정하거나 준비 함수를 실행할 필요 없이, SHEET_URL 스크립트 속성에 자기 시트 주소 전체를 넣고 첫 저장 때 기록 탭을 만들도록 요청한다. 기존 게임의 디자인, 조작, 두 놀이는 유지한다.

교사 코드 다운로드와 연습 숫자 전용 화면 단계는 제거했다. 이전 예제 두 파일은 Git에서 제외된 work-temp/lesson03-retired-files-20261001에 보관했다. 이전 검증 문서는 이력으로 유지하고 현재 기준 문서로 연결했다. 이전 예제 서버의 테스트 결과를 새 AI 생성 코드의 검증 결과로 제시하지 않는다.

120분 배분: 체험 10, 준비 10, AI에게 두 파일 요청 25, 첫 저장 20, 휴식 10, 저장 안내·랭킹 15, 친구와 확인 20, 보관 10.

## 공식 문서로 확인한 구성

- HTML 파일과 Code.gs를 같은 Apps Script 프로젝트에 넣고 웹앱으로 실행하는 구성: [Google HTML 서비스](https://developers.google.com/apps-script/guides/html).
- 프로젝트 설정에서 속성 이름·값을 저장하는 절차: [Google 스크립트 속성](https://developers.google.com/apps-script/guides/properties#manage_script_properties_manually).
- 웹앱 배포, 실행 주체, 테스트 주소와 배포 주소: [Google 웹앱](https://developers.google.com/apps-script/guides/web).
- 기존 배포의 새 버전 반영: [Google 배포 관리](https://developers.google.com/apps-script/concepts/deployments).

## 보존 및 한계

보호 파일 4개의 SHA-256은 최초 기준과 같고 instructor 객체는 Git HEAD와 같다. 기존 사용자 작업은 보존했으며 git diff --check를 확인했다. 커밋·푸시·외부 배포는 수행하지 않았다.

실제 Gemini에 프롬프트를 보내거나 Google 계정에 로그인·배포·Sheets 저장을 실행하지 않았다. 생성 코드의 저장 성공, 학생 계정의 권한, 다중 사용자 실행은 교사가 학교 계정으로 사전 확인해야 한다. 검증된 것은 강의 페이지의 구성·복사·레이아웃과 문서 절차이며 학생별 생성 앱의 정상 작동은 아니다.
