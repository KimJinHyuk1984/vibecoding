# 4회 운영 메모 — 우리 학교 분실물 센터

작성일: 2026-10-01. plan2.md의 네 번째 독립 프로젝트이며, 2시간 한 번에 모두 끝내는 시간표가 아니다. 체크 지점에서 쉬거나 다음 수업으로 이어간다.

## 도착점과 진행 순서

학생이 자기 물건의 연습 사진을 올리고, 다른 이용자가 특징·종류·장소·상태로 찾아볼 수 있는 앱을 만든다. 실제 전달을 마친 운영자는 시트 메뉴로 반환을 기록한다. 사진 인식 AI·소유자 자동 판정·연락처 수집은 기본 기능에 포함하지 않는다.

1. 도입: “내 이어폰, 누가 봤어?”와 로컬 모형으로 선택·저장·찾기·반환 체험.
2. 설계: 물건 하나가 시트 한 줄이며, 화면 정보와 관리 정보를 구분.
3. 화면: 새 채팅에서 AI에게 index.html 전체 요청. 실제 저장 전 미리보기 확인.
4. 저장 공간: 새 Sheets와 내 Drive의 별도 제한 폴더, 바운드 Apps Script.
5. 글자 저장: Code.gs 요청 → 두 파일 연결 → 나만 접근하는 /exec에서 시트·목록 확인. **v1**.
6. 사진: JPG·PNG 한 장을 Drive에 저장하고 물건번호로 읽기. 미리보기·완료·실패를 구분.
7. 검색: 검색어 AND 종류 AND 상태, 결과 수·빈 결과·6개씩 나눠 보기. **v2**.
8. 반환: 운영자 시트 메뉴에서 실제 전달 후 확인, 고유 물건번호로 상태 갱신.
9. 권한: Drive 원본 권한과 실행 계정·웹 앱 접근 범위를 따로 확인.
10. 시험·보관: 경계 파일·중복·사진만 실패·다른 계정·반환을 시험하고 **v3** 보관.

기본 프롬프트 7개, 선택 정렬 1개, 도움 1개. 학생은 코드 줄을 수정하지 않고 AI에게 두 파일 전체를 다시 받는다. 02·03·04·06의 긴 요청은 발표에서 두 조각으로 나뉘지만 복사는 전문이다. 코드 용어 설명은 프롬프트와 별도다.

## 계정·공간 준비

| 항목 | 수업 기준 |

학교 정책상 해당 배포 옵션이나 Drive 접근을 사용할 수 없으면 나만 보기로 시연하고 친구 접속은 미실행으로 남긴다. 개인 계정·전체 공개로 바꾸어 해결하도록 안내하지 않는다. 샘플은 자기 물건을 찍되 얼굴·이름표·학생증이 없도록 준비한다.

## 학생이 AI에게 만들게 할 데이터 계약

공개: 물건번호, 물건명, 종류, 특징, 발견장소, 발견날짜, 보관중/반환완료 상태. 관리: 등록시각, 사진파일ID, 반환시각, 요청번호, 저장상태와 복구용 부가 정보. 모든 텍스트는 표시용 문자열로 다루고 시트 수식·HTML로 실행하지 않는다. v1의 사진 없는 기록은 보존한다.

- 물건명·발견장소 최대 40자, 특징 최대 200자. 종류는 문구/의류/전자기기/기타. 날짜는 실제 있는 YYYY-MM-DD.
- 사진 단계의 신규 등록은 한 장 필수. JPG/PNG, 0바이트 초과, **1,048,576바이트 이하**. 이 값은 수업용 제한이며 Google의 공식 최대 업로드 용량이라고 설명하지 않는다.
- 화면의 accept 속성·파일명만으로 판정하지 않는다. 서버에서도 크기와 MIME, 파일 내용의 형식을 확인한다. HEIC·SVG·PDF·위장 확장자 등은 수업 범위 밖이다.
- 한 사용자 요청에 고유 요청번호를 유지한다. 성공 여부가 불확실할 때 같은 번호로 조회/재시도하며, 새 번호를 무작정 발급하지 않는다. 같은 번호의 다른 내용은 거절해야 한다.
- 서버에서 ScriptLock 등으로 같은 요청을 직렬 처리하고 요청번호→물건번호/파일 연결을 보존한다. 같은 이름을 가진 다른 물건은 허용한다.
- 파일 생성과 시트 저장은 한 번에 원자적으로 끝나지 않는다. 요청번호를 먼저 기록하고 파일에도 복구 가능한 식별을 남겨, 사진만 생성된 경우 기존 파일을 찾아 이어간다. 저장 완료된 행만 목록에 포함한다. 연결이 불확실하면 확인 필요로 멈춘다.
- 공개 목록 응답에 사진파일ID·요청번호·원본 파일명·운영 설정값을 보내지 않는다. 날짜 객체를 직접 전달하지 말고 문자열로 직렬화한다.
- 검색 조건 전체를 서버에서 적용한 후 최대 6개씩 반환한다. 필터 변경 시 첫 페이지. 기본 정렬도 고정하고, 선택 기능은 전체 결과 정렬 후 페이지를 나눈다.

이 계약은 교사용 확인 기준이며 이 저장소에 정답 서버 파일을 제공하는 의미가 아니다. 학생 AI 출력에 빠진 조건이 있으면 관찰한 증상과 현재 파일 전체로 보완 요청한다.

## 파일 전달·열람과 반환 구현 확인

Apps Script HTML 서비스의 `google.script.run`은 비동기다. form 요소를 전달하는 방식을 사용하면 파일 입력은 서버에서 Blob으로 받을 수 있으며, 이때 form이 유일한 인수여야 한다. 나머지 입력과 요청번호를 같은 form 안에 둔다. 성공/실패 처리를 분리하고 완료 전 입력을 지우지 않는다. 공식 문서의 방식은 AI 출력 점검용이다. [Google · 화면과 서버 통신](https://developers.google.com/apps-script/guides/html/communication)

이 강의는 Drive 보기 URL을 img 주소로 붙이는 방식 대신, 저장된 물건번호로 해당 사진을 서버에서 읽는 방식을 요청한다. 교사는 사진 읽기에서 완료한 행 조회, 지정 폴더 소속·휴지통 여부·허용 형식·크기 확인 후 이미지 데이터만 전달하는지 확인한다. 임의 파일ID를 받아 운영자의 다른 Drive 파일까지 읽는 공개 함수가 있으면 안 된다. `getBlob()`으로 파일 내용을 읽는 기능은 Drive 문서에서 확인할 수 있다. [Google · Drive File](https://developers.google.com/apps-script/reference/drive/file)

반환 함수와 내부 보조 함수는 이름을 `_`로 끝내 `google.script.run`의 호출 대상에서 제외한다. 메뉴용 확인 UI는 시트에서만 쓰고, 공개 웹 함수에 반환 분기를 두지 않는다. 단순 버튼 숨김·프런트 비밀번호로 대체하지 않는다. 공개 onOpen은 메뉴만 추가하며 반환 자체를 실행하지 않는다. [Google · Private functions](https://developers.google.com/apps-script/guides/html/communication#private_functions)

선택한 한 행의 물건번호·이름을 확인받고, 확인 후 잠금을 잡아 같은 번호를 다시 찾은 뒤 상태와 반환시각만 변경한다. 확인 창을 띄운 상태의 잠금 유지를 가정하지 않는다. 반환완료 반복 호출은 원래 시각을 보존한다. 제목/빈 행/여러 행 선택은 거절하고 사진·행은 삭제하지 않는다.

실행 계정이 운영자인 웹 앱은 운영자의 권한으로 사진을 읽어 이용자에게 전달한다. Drive 원본이 제한됨이어도 앱으로 전달된 사진은 앱 이용자가 볼 수 있다. 사진의 조회 범위는 웹 앱 접근 설정까지 함께 판단해야 한다. [Google · 웹 앱 권한](https://developers.google.com/apps-script/guides/web)

코드 저장과 배포 버전 변경을 구분한다. /exec는 같은 배포의 새 버전으로 갱신하고, 연습 종료 시 사용 중인 배포와 이전 배포를 확인해 보관처리한다. 시트·사진 파일은 별도로 남는다. [Google · 배포 관리](https://developers.google.com/apps-script/concepts/deployments)

## 실제 Google 계정 사전 시험표 — 이번 페이지 제작에서는 미실행

| 시험 | 기대 결과 |
| --- | --- |
| 글자 등록과 새로고침 | 시트 한 줄·목록 한 건, 연습 카드 제거 |
| 정상 JPG/PNG | 시트 한 줄·폴더 파일 한 개·사진 보기 정상 |
| 파일 경계 | 0, 1,048,575, 1,048,576, 1,048,577바이트 및 잘못된 형식. 크기 조건과 실제 형식 조건을 함께 판정 |
| 잘못된 내용 | 빈 필수값, 존재하지 않는 날짜, 허용 밖 종류·긴 글은 거절. 수식·HTML 같은 문장은 실행되지 않음 |
| 같은 요청 연속·동시 | 완료 기록·사진 각각 하나. 다른 요청의 동일 물건명은 별도 번호 |
| 응답 유실·부분 저장 | 같은 요청번호 유지. Drive 파일만 생겨도 복구 후 추가 파일 없이 완료 또는 확인 필요 |
| 사진 실패 | 이 수업용 파일만 잠시 휴지통으로 이동해 오류 시험. 글자 정보 보존, 복원 뒤 다시 시도 |
| 물건 범위 밖 사진 | 없는 물건번호·다른 폴더 연결·임의 파일ID는 반환하지 않음 |
| 검색·6개 페이지 | 7개 이상 데이터, AND 조건·0개·초기화·페이지 이동. 누락/중복 없이 조회 |
| 반환 | 운영자 한 줄 확인 후 변경, 취소 시 변화 없음, 재실행 시 반환시각 동일. 사진·행 보존 |
| 웹 이용자의 역할 | 반환 함수 직접 호출도 불가. 화면에 비밀번호·민감한 관리 칸 노출 없음 |
| 별도 계정 | 허용 계정은 앱 조회·사진·등록 가능, 시트 편집 불가. 범위 밖 계정은 앱 접근 불가 |
| 배포 갱신·중지 | 같은 /exec에 최신 변경 반영. 보관처리한 배포 접근 중지, 시트·파일 유지 |

부분 실패와 서버 검증 우회 시험은 교사가 격리된 연습 사본에서 수행한다. 학생에게 코드를 임의로 망가뜨리게 하거나 실제 분실물 원본을 삭제하게 하지 않는다. 파일 크기 시험의 적법한 이미지 준비도 교사가 한다. 크기만 맞춘 임의 바이트 파일은 정상 사진이 아니다.

## 로컬 도입 모형

lost-lab에는 우산·물병·이어폰의 모형 그림 세 개가 있다. 연습 사진 선택은 미리보기 안내만 바꾸고 등록 시 필통 하나를 추가한다. 같은 요청 반복은 추가하지 않는다. 검색어·종류·상태는 AND이며 반환은 상태만 바꾸고 전체 기록 수는 유지한다. 사진 읽기 실패 체크를 켜면 그림을 대체 안내로 바꾸지만 글자 정보는 남는다. 반환으로 카드가 사라질 때 포커스는 상태 선택으로 옮긴다.

이 모형은 브라우저 메모리만 사용한다. 실제 파일 선택·업로드·Drive 저장·서버 인증을 검증하지 않는다. 새로고침/초기화는 모형을 되돌린다. 실제 앱의 반환은 시트 메뉴 전용이며 체험의 반환 버튼은 역할 설명을 위한 것이다. 별도의 체크·제작 기록만 기존 저장 기능으로 브라우저에 보관한다.
