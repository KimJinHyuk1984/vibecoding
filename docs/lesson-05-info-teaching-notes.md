# 5회 운영 메모 — 우리 학교 정보 도우미

작성일: 2026-10-02. plan2.md의 다섯 번째 프로젝트다. 2시간 한 번에 모두 마치는 시간표가 아니라 결과를 확인하는 단위로 이어간다.

## 완성 목표와 흐름

학교 점심과 지역 예보를 외부 API에서 읽어 카드로 보여주고, 선택한 날짜의 자료로 세 질문에 답한다. 기본 답변은 규칙 기반이며 AI 호출로 표시하지 않는다. 학생은 AI에게 자연어로 기능을 요청하고 index.html·Code.gs 전체를 받아 실행한다. 교사의 정답 서버 파일은 제공하지 않는다.

1. 도입: “오늘 급식 뭐야? 우산도 챙겨야 해?”와 가상 API 체험.
2. 개념: 브라우저 → Apps Script → 외부 API, GET·JSON·POST의 역할.
3. 준비: 새 Docs·독립 Apps Script 프로젝트, 학교·날씨 지역·나이스 키 설정.
4. 화면: 연습 카드로 가독성을 먼저 확인.
5. 급식: 나이스 점심 조회, 결과 상태 구분, 실제 카드 연결.
6. 예보: Open-Meteo를 더해 두 출처를 독립적으로 조회. **v1 정보 조회**.
7. 캐시: 출처와 조건별 5분 보관, 원래 수신 시각 유지. **v2 캐시·오류 처리**.
8. 질문: 세 질문에 현재 자료로 답하고 없는 정보는 모른다고 안내. **v3 질문 도우미**.
9. 시험·공유·보관: 날짜 변경·부분 실패·캐시·근거와 이용 범위 확인.
10. 선택: 학교가 허용한 서비스가 확정된 경우에만 실제 AI API 확장.

11개 섹션, 프롬프트 9개(기본 7·AI 선택 1·도움 1), 체험 1·체크 3·제작 기록 1이다. 기본 앱에 Sheets 기록·파일 업로드·자동 트리거는 추가하지 않는다. 출처 연결과 현재 자료의 신뢰성을 익히는 데 집중한다.

## AI 생성 코드의 기술 확인 기준

### 급식 GET

- 고정 엔드포인트: `https://open.neis.go.kr/hub/mealServiceDietInfo`.
- 파라미터: KEY는 속성, Type=json, pIndex=1, pSize는 필요한 범위. ATPT_OFCDC_SC_CODE·SD_SCHUL_CODE·MLSV_YMD(YYYYMMDD)·MMEAL_SC_CODE=2로 학교·날짜·점심을 고정한다.
- HTTP 성공 여부와 응답 내부 RESULT를 모두 검사한다. 정상 서비스 배열의 head/row와 최상위 RESULT만 오는 경우를 구분한다. INFO-200 자료 없음, 인증·호출 한도 오류를 한 종류로 합치지 않는다.
- DDISH_NM의 줄바꿈은 표시용으로 정리하되 알레르기 숫자를 임의로 제거하지 않는다. 메뉴·학교명·오류는 HTML로 실행하지 않고 텍스트로 표시한다.
- 응답의 학교·급식 날짜·식사 구분이 요청과 일치하는지 확인한다. 여러 정상 row가 있다면 점심 결과가 누락되지 않게 처리한다. 다른 날짜 메뉴로 대체하지 않는다.

나이스의 메뉴 숫자는 알레르기 유발 식재료 표기다. 이 프로젝트는 메뉴를 원문에 가깝게 보여주며 개인의 섭취 적합성을 판정하지 않는다. 명세의 화면·필드가 바뀌면 포털의 최신 명세를 먼저 확인한다. [급식식단정보 공식 명세](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17320190722180924242823&infSeq=2)

### 날씨 GET

- 고정 엔드포인트: `https://api.open-meteo.com/v1/forecast`.
- latitude·longitude는 서버 설정을 읽어 유한수와 범위를 검증한다. daily에 temperature_2m_min, temperature_2m_max, precipitation_probability_max, timezone=Asia/Seoul, forecast_days=7을 사용한다.
- daily.time에서 선택한 YYYY-MM-DD의 인덱스를 찾고 같은 위치의 값과 daily_units를 읽는다. 선택 날짜가 없거나 필드가 null이면 확인 불가로 둔다.
- 표시: 최저·최고 기온 °C, **하루 중 최대 강수확률 %**. 현재 관측값·하루 내내 비가 올 확률·방과 후 특정 시각의 예보로 설명하지 않는다.
- 기온 0·음수와 확률 0을 유효한 값으로 취급한다. 없는 값을 Number(null) 등으로 0으로 만들지 않는다.
- `Weather data by Open-Meteo` 및 CC BY 4.0 링크를 화면에 표시한다. 좌표·선택 날짜·실제 수신 시각을 구분한다. 수신 시각은 예보 모델의 생성 시각이라고 쓰지 않는다.

응답은 시간 배열과 값 배열의 위치를 맞춰 해석하며, daily 값은 하루 단위 집계다. [Open-Meteo 예보 문서](https://open-meteo.com/en/docs)

무료 API는 비상업 용도와 호출 제한이 적용되고 교육 콘텐츠는 예시 용도에 포함된다. 수업용 앱에 광고·판매를 넣거나 운영 범위를 바꾸면 해당 조건을 다시 확인한다. 서버 호출이 같은 IP로 모일 수 있으므로 팀별 무한 새로고침을 만들지 않는다. [이용 조건](https://open-meteo.com/en/terms), [출처 표시·라이선스](https://open-meteo.com/en/licence)

### 서버·화면 연결과 캐시

- 브라우저는 Apps Script HTML 서비스의 google.script.run을 사용하고, 외부 통신은 서버의 UrlFetchApp으로 수행한다. 공개된 임의 URL을 받아 대신 호출하는 함수는 만들지 않는다.
- 스크립트 속성은 프로젝트 편집자가 볼 수 있으므로 편집 권한을 관리한다. 키를 포함한 전체 요청 URL·오류 원문을 그대로 로그나 화면에 출력하지 않는다. 화면은 이용자가 아니라 운영자가 정한 학교·지역만 조회한다.
- 한국 기준 오늘부터 6일 뒤까지를 화면과 서버에서 검증한다. 날짜 객체 직렬화·UTC 변환으로 하루가 밀리지 않도록 문자열 경계를 명확히 한다.
- 급식과 날씨 오류를 독립 처리한다. 한쪽 예외로 전체 요청을 버리지 않는다. 날짜 변경·조회 시작 시 이전 카드와 답변을 무효화하고, 요청 식별자로 오래된 응답을 무시한다.
- 캐시 키에는 출처·교육청·학교·점심·좌표·선택 날짜 등 해당 결과에 영향을 주는 조건을 포함한다. 서로 다른 API의 결과와 정상/빈 결과를 구분한다.
- 정상과 확인된 자료 없음은 300초 보관한다. 인증·HTTP·연결·형식 오류는 성공처럼 보관하지 않는다. 미확인 빈 응답을 정상 자료 없음으로 분류하지 않는다.
- 캐시에는 원래 fetchedAt을 함께 둔다. 재사용 시 현재 시각으로 갱신하지 않는다. CacheService의 조기 소실은 정상 가능성이므로 정확히 5분간 남는다고 보장하지 않는다.
- 실패 시 자동 무한 재요청하지 않는다. 429나 제공처 한도 오류는 쉬었다가 다시 시도하도록 안내하고 이전 자료를 최신처럼 보여주지 않는다.

UrlFetchApp은 외부 요청을 위한 권한이 필요하다. 필요 시 응답 상태를 직접 판정하도록 구성한다. [Google UrlFetchApp](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app)

캐시는 영구 저장소가 아니며 지정한 시간보다 일찍 삭제될 수 있다. [Google Cache](https://developers.google.com/apps-script/reference/cache/cache)

### 기본 질문 도우미

‘급식 알려줘’, ‘날씨 알려줘’, ‘우산 필요해?’ 세 문장만 처리한다. 앞뒤 공백을 제외한 나머지 입력은 지원 질문을 안내한다. AI·자유 언어 이해라고 표현하지 않는다. 현재 날짜로 조회한 자료의 상태를 먼저 확인하고, 메뉴와 예보를 그대로 설명한다.

우산 안내의 60% 이상 기준은 수업에서 정한 규칙이다. 59/60을 경계 시험하고 0과 null을 구분한다. 실패·미준비·없는 데이터로 판단하지 않으며 낮은 수치를 비가 안 온다는 보장으로 쓰지 않는다. 기본 질문 자체는 새 API 요청이나 질문 저장을 만들지 않는다.

## 선택 AI 확장의 진입 조건

서비스명, 공식 API 문서, 현재 모델, 미성년 학생 대상 앱 허용 범위, 데이터 처리, 호출 예산을 학교가 확인한 경우에만 선택 프롬프트를 사용한다. 괄호가 비어 있거나 문서 확인이 불가하면 엔드포인트·인증·응답 형식을 추측해 실행하지 않는다. 선정 전에도 기본 정보 조회와 규칙 답변은 독립적으로 완성된다.

2026-10-02 확인한 Gemini API 추가 약관에는 API 이용자의 18세 이상 조건과 18세 미만 대상/접근 가능 앱 사용 제한이 있다. 따라서 이 고등학생 앱의 기본 제공자로 채택하지 않았다. 일반 AI 채팅 제품 이용 가능 여부와 별도 API 약관을 혼동하지 않는다. [Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms)

선정 후 추가할 속성: AI_API_KEY, AI_API_URL, AI_MODEL, AI_ENABLED(false 기본값). 실제 인증 헤더·JSON 요청·응답 추출은 선정된 서비스의 공식 명세를 따른다. 키를 URL 파라미터나 프런트 코드에 넣지 않으며 운영자가 정한 엔드포인트로만 보낸다.

선택 구현의 확인 기준:

- 학생이 보내기를 눌렀을 때만 HTTPS POST. 최대 200자 질문과 서버가 조회·검증한 같은 날짜의 자료를 전달한다. 브라우저가 위조한 카드 내용을 근거로 사용하지 않는다.
- 자료·사용자 질문 속 문장을 시스템 지시로 승격하지 않는다. 참고 자료 외 사실을 지어내지 않게 요청하며, 이 지시만으로 정확성이 보장된다고 말하지 않는다.
- 학교·날짜·출처는 서버가 붙인다. 모델이 만든 출처 URL을 신뢰하지 않는다. 답변은 텍스트로 표시하며 API 키·시스템 설정은 참고 자료로 보내지 않는다.
- 운영자가 정한 분당·일일 한도와 중복 요청 방지를 서버에서 시행한다. 학생이 버튼 제한을 우회해도 무제한 호출할 수 없게 한다. 장기 한도를 쉽게 사라지는 캐시 하나에만 의존하지 않는다.
- API 오류·빈 응답·한도에 대한 안내와 기존 규칙 답변 복귀가 가능해야 한다. UI에서 AI와 규칙 답변을 구분한다.
- 허용된 계정으로 켜기/끄기·중복 클릭·범위 밖 질문·자료 부재·공격적인 자료 지시를 시험한다. 시험 종료 후 AI_ENABLED=false로 되돌리고 외부 호출이 멈추는지 확인한다.

| 선택 AI | 서비스 선정 후에만 인증·POST·응답·근거·한도·false 중지 확인 |

실제 Google 계정의 권한 승인·배포·학생별 AI 생성 코드 실행은 이번 페이지 작업에서 수행하지 않았다. 이 환경에서 공개 API 엔드포인트도 읽기 호출을 시도했으나 네트워크 fetch가 실패해 실제 응답을 검증하지 못했다. 공식 문서를 검토한 내용과 계정에서 실행한 결과를 구분한다. 키를 구하거나 요청 제한을 늘려 이 환경의 실패를 우회하지 않았다.

## 도입 체험의 정확한 범위

info-lab은 브라우저 메모리로 두 날짜와 여섯 상황을 표현한다. 정상·급식 없음·급식 인증 오류·날씨 연결 오류·확률 null·확률 0이다. 가상 날짜 A/B의 확률은 60/59로 경계를 비교한다. 실제 메뉴·예보가 아니다.

첫 조회는 모의 요청 2회, 같은 조건 재조회는 캐시 2건 재사용, 5분 진행 뒤 재조회는 2회 추가다. 출처별 캐시로 한쪽 오류만 재시도할 수 있다. 상황 선택을 바꾸면 연습을 위해 캐시를 비우며, 실제 앱에서 API 실패가 자동으로 캐시를 비운다는 뜻은 아니다. 날짜 변경·시계 진행은 이전 카드·답변을 지운다. 초기화는 진행 중 타이머도 무효화한다.

제한된 select로 질문을 고르면 규칙으로 답한다. 실제 외부 GET·POST, API 인증, 무료 사용 한도, CacheService 동작, AI 생성은 시험하지 않는다. 기본 사이트에 외부 런타임 요청·계정 입력을 넣지 않았다.

5회 피드백 이후 마지막 6회를 작성한다.
