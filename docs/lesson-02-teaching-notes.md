# 2회 운영 메모

## 수업 목표

학생이 자신의 무한의 계단 게임에 적용할 요구사항과 확인 방법을 정하고, 디자인과 게임 규칙을 따로 수정한다. 친구와 정상·경계·예외 상황을 테스트하고 버전별 코드와 결과를 Docs/Drive에 보관한다.

1회의 자유로운 첫 변경에서 한 단계 나아가, 이번에는 변경 전에 완성 기준을 명시한다. 기본 조작은 계속 ← 방향 전환, → 바라보는 방향으로 한 칸 올라가기다.

| 보관 | 15 | 30초 작품 소개, v3 코드·화면·결과·친구 피드백 보관 |
| 합계 | 120 | 휴식 포함 |

## 준비와 진도 차이

- 1회 게임, 제작 채팅, 보관한 전체 HTML 코드를 준비한다. 채팅이 없으면 새 채팅에 전체 코드와 PROMPT 01을 함께 붙인다.
- 코드도 없으면 페이지의 보충 안내에서 1회 첫 제작 프롬프트로 복구한다. 복구 시간이 길어지면 옆 친구와 테스트 역할을 먼저 맡아 수업에 참여하게 한다.
- 학교에서 허용한 계정과 실행 환경을 계속 사용한다. 이번 수업에는 외부 API, 결제, 배포, 학생 정보 수집이 필요하지 않다.
- Gemini의 답변만으로 확인 완료를 체크하지 않는다. 실제 실행 결과가 요구사항과 같은지 확인한다.
- ‘디자인만 변경’과 ‘규칙 추가’를 따로 보낸다. 디자인을 바꾸다 조작이 달라지면 규칙 추가 전에 복구한다.
- 빠른 학생은 선택 프롬프트 06으로 실제 코드의 상태와 조건을 설명받고 실행으로 검증한다. 필수 수업에서 추가 기능을 늘리지는 않는다.
- 두 모드 모두 유지하며 제한 시간을 추가하지 않는다. 무한 모드는 21칸까지 가야 하고, 도착 모드는 정확히 20칸에서 멈춰야 한다.

## 체험 위젯

- 테마 체험은 기본·우주·도서관 세 가지다. 같은 게임 인스턴스의 제목·색·계단 모양을 바꾸며 점수·위치·방향은 유지한다.
- 20칸 도착 체험은 해당 동작만 보여주는 보충 예제다. 학생의 완성 앱에는 ‘끝없이’와 ‘20칸 도착’ 두 모드와 전환 안내가 모두 있어야 한다.
- 예제는 직접 작성한 로컬 코드이며 학생 계정의 AI에서 생성한 결과라고 표시하지 않는다.
- 발표 기본 흐름에서는 복구 안내, 도착 체험, 원리 프롬프트를 생략한다. S 키로 보충 조각을 포함할 수 있다. 웹 페이지에서는 모두 읽고 사용할 수 있다.
- 게임에 키보드 초점이 있으면 방향키가 게임을 조작한다. 다른 발표 조각으로 이동할 때는 게임 밖의 컨트롤로 초점을 옮긴다.

## 완료 기준과 다음 연결

Docs에 요구사항·확인 방법, v1/v2/v3 전체 코드, 변경 전후 화면, 여섯 가지 실제 테스트 결과를 남긴다. 3회에는 이 게임의 기록을 Google Sheets에 연결할 계획이며 3회 본문은 사용자 피드백 후 작성한다.
