# 바이브코딩 시리즈 작업 상태

## 현재 사용자 지시 — 기존 1~3회를 1회로 통합

- 직전 대화에서 시간 제한을 두지 않고 하나의 프로젝트로 진행하는 흐름을 논의했고, 사용자가 “현재 1회, 2회, 3회를 합쳐서 1회에 작성해줘. 내용 흐름도 잘 생각해서 작업하자”라고 제작을 지시했다.
- 직접 제작 지시에 따라 통합 1회를 완성한다. WORKFLOW 단계별 실행 요청은 아니므로 별도 중간 승인 절차는 추가하지 않는다.
- 1회 제목: 내 게임을 우리 반 서비스로. 기본 흐름은 소개·체험 → 첫 게임 → 내 취향 → 시트 기록 → 공유 랭킹 → 보관·다음 아이디어다.
- 학생은 코드를 읽지 않는다는 전제를 유지한다. 저장용 Code.gs도 AI에게 직접 요청하고, 자신의 게임 HTML을 index.html로 연결한다.
- 시간·분 단위 안내를 제거했다. 게임 실행, 디자인 반영, 실제 시트 저장, 친구 기록 확인을 다음 단계 기준으로 삼는다.
- 최근 5판 기록·휴대폰 개선·20칸 도착은 완성 후 선택 미션이다. 문제 해결은 필요한 순간 사용하는 도움으로 분리했다.

- 이 직접 제작 지시에 따라 회차 페이지를 완성하는 범위로 진행했다. WORKFLOW.md를 순차 실행하라는 요청은 아니므로 별도의 단계별 승인 요청은 추가하지 않았다.

## 후속 피드백 — 내 게임에서 저장 코드까지 직접 요청

- 사용자 요청: index.html은 자신이 만든 게임 HTML로 사용하고, Apps Script에 넣을 저장 코드를 AI에게 직접 요청한다. 교사 코드를 받아 사용하는 단계를 없앤다.
- 3회를 자기 게임 HTML 제공 → Code.gs 요청 → 게임에 저장 기능 연결 → 두 파일 붙여넣기 → 실제 점수 저장 → 랭킹 개선으로 재구성했다.
- index.html은 소문자로 통일한다. Code.gs와 같은 Apps Script 프로젝트에서 실행한다. 별도의 연습 숫자 화면은 만들지 않는다.
- 시트 주소는 프로젝트 설정의 스크립트 속성 SHEET_URL에 전체 주소를 붙여넣는다. 학생에게 코드 줄 수정·ID 추출·준비 함수 실행을 요구하지 않는다.
- 학생용 다운로드 링크는 제거했다. 이전 예제 파일은 Git 제외 작업 폴더로 보관하여 현재 강의에서 사용하지 않는다.
- Google 공식 문서에서 HTML 서비스·웹앱·스크립트 속성·배포 갱신 절차를 확인했다. 실제 학교 계정의 생성·인증·저장은 별도 사전 확인 대상이다.

## 교실에서 확인할 환경

- 실제 학생 계정의 Gemini·Canvas 접근은 학교 정책에 따라 별도 확인한다. 실제 계정으로 Gemini에 프롬프트를 전송하는 검증은 수행하지 않았다.
