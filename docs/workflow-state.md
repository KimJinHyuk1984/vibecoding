# 바이브코딩 시리즈 작업 상태

## 사용자 지시와 이번 범위

- 2026-09-30 사용자 지시: 기존 계획의 13·14·16회를 제외하고 시리즈로 제작. 1회부터 시작하며, 소개를 실습 앞에 배치하고 학생이 클릭으로 프롬프트를 복사할 수 있게 구성. 한 회 작업 후 피드백을 받고 다음 회차로 진행.
- 2026-09-30 피드백 반영: 도입 게임을 무한의 계단으로 변경. ←는 방향 전환, →는 올라가기. 체험 위젯·프롬프트·테스트·오류 예시를 같은 규칙으로 수정했다. 첫 실습은 제한 시간 없이 진행한다.
- 사용자 후속 지시 “좋아~ 2회로 가자”: 1회 피드백을 마무리하고 2회 제작을 진행했다. 이번 작업의 범위는 2회까지다.
- 이 직접 제작 지시에 따라 회차 페이지를 완성하는 범위로 진행했다. WORKFLOW.md를 순차 실행하라는 요청은 아니므로 별도의 단계별 승인 요청은 추가하지 않았다.
- 1~12회는 기존 순서 유지. 기존 15회의 사용자 테스트·개선을 새 13회로 편성했다. 새 13회는 12회 개인 미니 앱을 개선하는 흐름이다.
- 시리즈 목록에 13회를 등록했으며, 1·2회만 ready다. 3회 이후 본문 파일은 만들지 않았다.
- 원본 PPTX는 읽기 전용으로 유지하고 Git에서 제외했다. 원본의 사진, 노트, API 키를 공개 페이지로 옮기지 않았다.

## 현재 상태 — 2회

- 구현: `lesson-02/index.html`
- 진행 상태: 2회 사용자 피드백 대기
- 최신 검증: `docs/lesson-02-verification.md`
- 제목: 같은 게임, 완전히 다른 스타일
- 시간: 120분(다시 열기 10, 테마 체험 10, 설계 15, 디자인 20, 휴식 10, 규칙 추가 20, 테스트·수정 20, 보관 15)
- 섹션: `reopen`, `compare-styles`, `write-brief`, `remix-design`, `take-a-break`, `add-rule`, `test-and-fix`, `keep-versions`
- 프롬프트: 7개. 현재 코드 파악 → 요구사항 → 디자인 → 20칸 도착 모드 → 오류 수정 → 원리 설명(선택) → 코드 보관.
- 위젯: 테마 변경 게임 1개, 20칸 도착 게임 1개, 체크리스트 3개, 제작 기록 1개.
- 발표: 기본 28조각, 보충 포함 31조각. 보충은 코드 복구 안내·도착 체험·원리 프롬프트.
- 1회와 시리즈 목록에서 2회로 이동하는 링크를 연결했다. 1회 게임의 기본 무한 모드는 유지했다.
- 다음 작업: 2회 피드백 반영. 사용자의 다음 회차 진행 지시 전에는 3회 본문을 작성하지 않는다.
- Git 커밋·푸시·Pages 설정·배포: 미실행

## 교실에서 확인할 환경

- 실제 학생 계정의 Gemini·Canvas 접근은 학교 정책에 따라 별도 확인한다. 실제 계정으로 Gemini에 프롬프트를 전송하는 검증은 수행하지 않았다.
- 첫 수업에는 API 키·결제·공개 링크 생성이 필요하지 않다. Gemini 미리보기 또는 단일 HTML 파일로 실행한다.
- 템플릿에 지정된 강사 사진 파일은 제공되지 않았다. 공통 기능이 이름 이니셜로 대체 표시한다.
- 원본 슬라이드 이미지를 새 페이지에 사용하지 않았으므로 원본의 전체 이미지 OCR·공개 적합성 심사는 이번 제작 범위에 포함하지 않았다.
